# 电影级制片：Qwen 电影感 V1 九宫格 → Pika 多参考

仅在用户明确提出“电影级制片”或同意采用本流程时使用。本流程是用户指定的制作路线，不意味着已验证所有题材都优于其他路线；本次具体模型、素材或制作范围另有明确要求时优先。先通过 `aid_status` / 工作流检查和 Pika 的只读预览核对可用性；缺依赖、额度不足或任务不确定时明确报告，不擅自换 LoRA、供应商或缩减参考数量。生成按当前项目授权执行，关键词不是无限预算或批量重试授权。

1. **剧本与详细导演稿**：先完成适用范围内的完整故事、人物目标、因果与前后承接，再按叙事需要设计场次/镜头、明确对白、景别、视轴、人物和道具状态、镜头运动、声音与段落时长。写完整视频执行提示词，复杂动作写明每秒先后动作、重心、手脚/武器、接触、受力、对手反应和镜机如何跟随；速度随剧情，必要时一秒可有多个衔接动作但须留出观看重点。按此前用户认可的 [Pika H3 Flex 分层写法](pika-h3-flex-structured-prompt.md) 写时间线、声景和配乐，保留项目对白及语言要求。
2. **场景基础分镜**：使用已核验的 Qwen-Image-2.1 电影感 LoRA **V1** 工作流，先生成能承载该场景人物、空间、服装、光线和视觉风格的基础分镜；按项目锁定既有人物素材与方向，并记录场景起点、结束状态。不能用 V2 或不带 LoRA 的工作流冒充 V1；名称、模型路径和可用性以当前实际配置确认。
3. **每个场景的九宫格**：把对应基础分镜作为 Qwen V1 的实际图片参考，围绕剧情和视觉简报生成 3×3 板。每格标明其对应段落、镜号或同镜状态、景别/角度、人物站位、动作与道具状态；图外记录编号，不把文字、边框或拼贴带进成片。九格按阅读顺序安排；同镜连续状态可以服务一段动作，多个不同景别可以组成 3–4 个有明确切点的剧情镜头。场景与生成段不必强行一一对应：先按故事与模型时长分段，复杂场景可分多个九格段；每个段实际选择九张图。不要把九格机械解释成九次剪切或均匀时间戳。
4. **裁切与素材核验**：保留原板，按实际分格裁成九张不带编号的独立图并记录 P01–P09 到素材 ID、场景、镜号、状态和预期顺序的映射。逐格检查真实画幅/有效像素、人物身份、肢体、光线、地理空间、视线、运动方向、道具归属和邻格接续；错格、分界、拼贴、面部或肢体缺陷先修复再提交。九宫格单格长宽只有整板的约三分之一；必要时先提高整板可用分辨率或重新生成，不把插值放大当成真实细节。
5. **Pika 九图成段**：使用 `pika/pika-h3-flex/reference-to-video`，在已配置 Pika 服务实际提交 `assets.reference_image_1` 至 `assets.reference_image_9`；检查预览中九个 `references` 与素材/顺序吻合。按 [Pika 分层提示词](pika-h3-flex-structured-prompt.md) 将每图的角色和 N−1 段动作衔接写进同一个 prompt，注明需要的真实切点、每段首尾状态和跨段交接；不要把参考图写成已经锁定的首帧或帧级关键帧。Pika image-to-video 是首帧/可选尾帧路线，不把九图塞给它。每次按 API 当前时长/分辨率及素材数量限制规划，多段作品先保存项目并绑定 projectId / shotId。
6. **验收与连续性**：查看整段与关键接触点、镜位转变、段首段末，核对角色/服装、空间、物件、动作逻辑、原对白及声画，记录跳变和缺失。相邻段接续以实际已接受成片末态为准，下一段据此重做或调整参考图与提示词，不只沿用计划中的末帧。真实剪辑点允许切镜，连续长镜出现无法通过路径解释的构图跳变则修正。效果须实际审看，禁止只因九图或提示词完整就宣布连续或电影级。

九图参考为条件引导而非九个确定时刻；如必须严格锁定某一帧、镜头顺序或精确对白，先按真实接口能力选择拆段、首尾帧、配音和剪辑等可验证手段。具体作品成本取决于场景、图板、视频段、模型时长和实际重试次数；事先列数量与估算，不默认整片全部重跑。

依据：用户 2026-10-31 指定此流程；此前《荆棘之约》九图 Pika 对照中用户认为结构化提示词版更流畅，但仍有构图跳变，且语言/细节同时变化，不能单独归因。此新端到端流程尚未做完整成片对照。
