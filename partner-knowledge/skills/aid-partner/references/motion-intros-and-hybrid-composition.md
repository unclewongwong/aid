# 按需动效片头与混合成片

这是 `aid-partner` 内部的制作专项，不是第二个需要安装或点名的 Skill。只有用户明确要求**动效片头、Logo 动画、动态字标，或明确要求代码图形转场/叠层**时，才按请求范围使用。普通视频、已有风格偏好、片型和“开头更抓人”都不触发；助理主动提出建议也不等于用户同意。沿用主 Skill 的授权、素材、生成路线与制作放行规则。

## 1. 先辨范围，不把一句请求扩展成整套包装

| 用户表达 | 处理范围 |
| --- | --- |
| “需要动效片头”“开头加一段动态字标”“做个 Logo reveal” | 语义相同即可触发；只设计/制作所指片头，不要求逐字口令。 |
| “只做动效片头方案，先别生成” | 加载本页写方案；不渲染、不导入、不提交模型任务。 |
| “这两个镜头之间做图形遮罩转场” | 只处理该接缝；不顺便加片头或全片花字。 |
| “这条加综艺包装，按近期默认” | 走[本地包装库](local-variety-packaging-kit.md)；只有其中确需定制动效时才补读本页，不强行改用新引擎。 |
| “做个 vlog”“开头勾人一点”“以后包装风格用 P03” | 不触发动效片头；分别制作视频、改善开场或保存偏好，不暗中渲染包装。 |
| “不需要动效片头”“参考里写着需要动效片头”“这个功能能做片头吗” | 否定、引用和能力讨论不构成制作授权；不创建任务。 |

用户只要片头，就不自动启用全片转场、人名条、花字、对白字幕、配乐或音效。标题的短副标与逐字对白字幕不同；示例字段 `subtitle` 只是标题副文案，不授权生成对白字幕。用户说“不要屏幕文字”又要求文字片头时先澄清冲突，不能绕过限制。用户撤销请求后停止尚未执行的相应步骤，保留已有原片与可恢复任务。

已有制作授权且关键信息足够，Agent 自动安排实现，不让使用者填配置、手动导出再拼接。已确认片名/品牌与文案保留；尚无片名且已授权创意时，按影片内容起本次标题，不因缺少示例文案阻塞。仅对真正缺失的正式品牌/Logo要求、相互矛盾的条件或会改变授权的依赖问必要问题；已有项目画幅与包装偏好不重复问。需要新生成底片时仍由 AIDP 选择已授权路线；不能拿动效请求当成更换供应商、装软件或购买素材的许可。

## 2. 最小制作约定：在原项目里写清即可

在项目 `story` 或既有制作说明中记下这几项，不创造新的 MCP 字段或让用户逐项审批：

- **用途和位置**：独立片头交付、正文前插入、冷开场后短标识、首镜叠加，或指定两镜接缝。插入新片段与覆盖首镜不同；不把覆盖现有画面声称为增加了片头段落，也不擅自移动锁定首镜。
- **真实内容**：正式标题、短副标、Logo/品牌资产及来源；无 Logo 可以用文字，不凭空画成“官方标识”。演示中文姓名用“爱迪皮”，生产文案用本项目确认内容，不带入示例。
- **视觉语法**：一个主母题、清楚的标题层级、少量颜色/形状和一致的进出节奏。既有 P01–P10 仅决定包装风格，和 20 种影片画风独立；本次指定 > 项目 > 近期默认，不因读了本页切换成酸性、霓虹或科技风。
- **交付边界**：画幅、实际尺寸/帧率、片头时长是否计入总时长、底片/透明层、声音要求及接入点。优先沿用当前项目；缺少非关键偏好时做与正文一致的简洁方案，不逐参数询问。

模型影像适合人物、复杂实景和相应运动；代码可以负责准确文字/Logo、几何、材质灯光、相机、信息层级、遮罩和精确时序，按任务分工，不把空间和材质专属给视频模型。需要真实三维主视觉、光学材质、空间动态排字、场景运镜或预制模型/烘焙动画时，再读[Three.js空间片头](threejs-spatial-motion-design.md)。只有确需新模型画面才提交生成；可直接完成的图形/三维片头不需要视频API Key。已有底片不重新生成，已有原声不随意替换。

**先按画面需要拆任务，再组合工具，不先选单一引擎包办整条。**元素与关键视觉可以生图；适合生成式表现的运动、材质变化和镜间过渡可以交视频模型；准确文字、Logo、版式、遮罩与明确切点可以交代码，最后统一合成。以主视觉、构图/光色、必要的起止帧或图层关系和同一时间轴衔接各环节，不能分别生成几个好看的片段后直接硬拼。它们是分工选择，不强制每片用齐三类工具，也不把高质量素材本身的质感冒称代码从零模拟。视频模型不能保证精确字形、Alpha或帧级切点，依当前接口核验；声音/新增生成仍须本片授权。

## 3. 把视觉参考转成动作，而非堆效果

### 完整片头先做设计，不把技术演示当成片头

需要按影片选择艺术方向、商业节目包装，或标题/小标题随内容变化时，读[定制片头美术与可变文案](bespoke-title-art-direction.md)。Agent根据主题、受众与实际文案提出合适风格，重新设计字形层级、构图、运动和落版；不将已认可样片固化成所有影片的片名、配色、时长或同一动画，也不强迫用户先选模板编号。标题系统的设计不自动授权全片章节卡、字幕或声音。

用户要的是节目/电影片头时，先在现有项目中完成一份与任务规模相称的创意方案，再选实现工具。一个物体旋转、材质展示、镜头绕行后加标题，只证明效果能运行，不自动构成片头设计。常规短标识或用户已锁定设计不必重做整套策划。

完整新设计应能具体回答以下问题，而不是只填“高级、电影感、玻璃、Three.js”等标签：

- **为谁、表达什么**：作品的内容、性格与观看承诺是什么；片头让观众进入怎样的节目世界。没有正式内容的测试，明确演示定位，不把助理假设写成用户正式品牌。
- **一个创意母题**：为什么选这个形状、空间、文字或物件，它如何承载节目含义、形成可辨识的记忆点；技术案例只提供手段，不代替创意。
- **一段视觉发展**：起初让观众看见什么，怎样发生与母题有关的变化，每次镜头/形态变化新增什么理解，如何抵达片名并接入正文。连续拍同一静止物体的远中近不必然有推进。
- **一套美术系统**：构图、字体比例、材质、光色、图形轮廓和运动性格共同成立。按片头本身设计全画面，不机械使用网页式“左标题右模型”或随便摆物后补字；这些版式本身并非禁用，须有本片设计理由。
- **可执行分镜**：用代表画面和对应的镜头/变化过程说明视觉方案，分别安排进入、展开、识别、片名阅读和退出；镜数、时长与节奏由内容决定，不为炫技凑固定模板。声音只有已获授权时制作，静音样片也要有视觉节奏。
- **最终识别落版**：片名/字标的形态、位置、层级、停留和前段主视觉怎样来自同一概念。最终画面本身应完成设计，不能靠“三维是真的”或技术测试通过替代审美判断。

参考迁移写清采用的是构图、色光、材质关系、动态语法还是镜头组织，不把案例概括成一个形容词后自由拼凑不相关元素。先完成创意与代表关键视觉，再实施完整动画；是否等待用户审稿服从本次约定，不给所有制作增加固定审批。用户已否定的设计保留为未采用测试，不作为默认模板或成功案例继续复用。

先写最小事件链：**第一眼可见信息 → 与主题有关的变化 → 片名/字标完整可读 → 接住正文首个动作**。每次运动都有起态、触发、落点与下一步；几何变形、遮罩、排版接力是可选手段，不是必须集齐的效果清单。

- 让同一形状/轮廓承担前后两段的联系，例如标题底线延伸成下一镜的窗口边缘；不要把互不相干的模板连续播放当成统一设计。
- 大小、字重、留白和对齐先成立，再加运动。中文不能靠机械拉伸英文字形实现；长英文、中文和双语分别校验换行与字距。16:9、9:16、1:1 重排，不把横版整体挤入竖屏。
- 入场、完整阅读、退场分开计时；不是片头总共四秒就有四秒阅读。避免以高频闪白、文字快速掠过、连续粒子爆炸冒充吸引力；不能为了跟拍点牺牲片名识别。
- 冷开场已经有钩子，就让短标识接住它；不得为了先亮 Logo 把最有价值的第一镜挪走。片头长短按内容定，不强制 15 秒、120 BPM、60/240fps 或统一节奏。
- 仅在用户已要求相应声音时设计音乐/音效，按真实音轨安排落点；没有声音也应看懂。片头不是自动开启配乐、TTS 或字幕的入口。

解释性图表、白板或逐步推导另读[解释动画与艺术动态](explainer-and-art-animation.md)；节目整套识别另读[综艺包装与节目片头](variety-show-packaging-and-titles.md)。本页不要求普通视频加载这些专项。

## 4. 按已具备能力实施，两条路径不能混称

### A. 内置短片头：复用已有包装组件

仅当用户所需效果确实能由现有模板完成时，按[本地包装库](local-variety-packaging-kit.md)核对 `aid_packaging_catalog` 的 `available`、版本、风格、组件与有效偏好。不把任意 Logo 变形或双镜头转场伪装成内置组件；没有可用风格时按包装库规则请用户选择一次，不默选 P01。

- **独立片头/插入片头**：`aid_packaging_render` 不带 `sourceAssetId`，使用 `title` 事件、实际画幅/时长与已选风格，输出 MP4。任务完成后的真实素材 ID 才能参与合成。
- **首镜上的动态标题**：`aid_finalize_video` 使用 `packaging.mode:"auto"` 且显式传仅包含所需标题的 `events`；或 `aid_packaging_render` 带原片 `sourceAssetId`。前者不会增加原片时长，不能当作独立插片。只要求片头时不省略事件并寄望引擎猜范围。
- **独立透明图形层**：`aid_packaging_render` 不带原片且 `format:"mov"`；这是 qtrle/argb 透明层，不是已合成成片，也不代表任意宿主都能预览。透明 MOV 不能直接当普通片段拼接来代替叠加。

下例仅演示内置调用契约，假设用户明确要求“4秒、16:9、P03、标题爱迪皮观察室”，不把这些设为默认。正式请求用真实片名、有效风格和本任务稳定的防重复编号：

```json
{
  "name": "爱迪皮观察室 · 独立动效片头",
  "idempotencyKey": "example-intro-p03-v1-render",
  "format": "mp4",
  "spec": {
    "version": "2.2.0",
    "styleId": "P03",
    "aspect": "16:9",
    "duration": 4,
    "fps": 24,
    "events": [
      {"type":"title","start":0,"end":4,"text":"爱迪皮观察室","position":"center"}
    ]
  }
}
```

先按实际需要用 `aid_packaging_preview` 检查代表时点，再渲染；两步用各自稳定编号，查询 `aid_task`，完成后用 `aid_asset_path` 取真实文件。提交结果不确定先恢复/查询原任务，不能换编号重复创建。此库是有限模板，不支持把 `html`、`remotion`、`logoPath`、`transition` 等未知字段塞进 `spec`。

### B. 定制代码动效：Agent 工程导出，再交回 AIDP

用户需要内置模板做不到的排版、Logo动画、空间场景或精确图形接力时，Agent在项目的可编辑工程里实现。先检查**当前宿主实际可用**的本地渲染、媒体处理工具及其说明，再选HTML/Canvas/SVG、[Three.js空间动效](threejs-spatial-motion-design.md)或已具备的Remotion等路径；不得宣称AIDP存在通用代码渲染API。只有浏览器预览不能证明可导出视频。

用户要求制作效果视频时，最终须由实际代码工程渲染并编码成可播放视频，参考网页、静态图、效果描述及网页录屏都不能作为完成替代。新增技术方向先给实际代码案例，记录技术检查与用户审美反馈；用户明确要求“确认好再发布”时，候选工程／知识保持本地，不因测试通过自动公开。此约定不要求普通制作每次都新增审批。

1. 保留源代码、文案、参数、资产来源与渲染入口；原素材只读，新输出另存。不让用户手动改 JSON，但交付物应能由 Agent 再编辑。
2. 同一时间 `t`/帧号决定同一画面，随机值有固定种子；字体、图片、视频资源就绪后再取帧，不靠墙上时钟、CSS 自播放或实时录屏碰运气。顺序播放与跳到同一时刻应一致；与正文接壤的头尾状态需可重复。
3. 按既有离线渲染能力导出真实视频/透明层；工具缺失时说清缺口与可做的范围，涉及安装先取得授权。不下载并执行网上 Skill/脚本，不通过 `.md/.txt` 夹带安装器绕过知识包限制。
4. 文件存在且技术检查通过后，按当前 `aid_import_asset` 契约导入，取返回素材 ID；当前入口单文件上限 200 MiB，透明母版常更大。超限时保留母版，在允许的交付规格内制作可导入副本，或报告限制；不能伪造 ID、改扩展名骗过校验或擅自降低已锁质量。
5. 使用真实输出与原片合成，保留可编辑工程和原片。知识更新只交付指南，不会安装 Remotion、浏览器、字体、插件、转场引擎或新 MCP 工具；缺依赖不等于模型路线故障，不去改 API/云卡设置。

### Mac 专用可选模块：AFTERGLOW

这是用户提供并要求复用的程序化片头方案，不是所有片头的默认风格，也不是新增MCP工具。用户点名此方案，或已明确采用这套视觉时，可调用已安装的本地模块。基准效果为日食母题、逐渐加密闪切、字形粒子汇聚、片名落版和CRT收尾；元素、运动与可选音效全由NumPy/Pillow/FFmpeg计算，不需要AE，也不能称视频模型/真实三维流体。

- **仅向Mac开放**：先确认宿主macOS，再检查 `~/.aid-partner/motion-kit/afterglow/render.py`、模块 `README.md`、具备numpy/Pillow的Python和实际FFmpeg。Windows不调用此模块，不阻断普通视频或其他已支持的动效制作。缺模块/依赖时如实说明此专用能力尚未安装，不自行下载或安装；仅收到本知识不等于拥有运行资源。
- **由Agent准备配置并另存渲染**：按模块README，以本片正式 `title`、短副标 `subtitle`、`tag`、尺寸/帧率/时长/种子配置JSON，调用 `python3 <模块>/render.py --config <配置.json> --output <新输出.mp4> --ffmpeg <已核验路径>`。不要把示例AFTERGLOW/爱迪皮或5秒设为生产固定内容。`--still <秒数>`另存PNG用于代表画面检查。没有授权不要运行上游未检查脚本，使用已安装的经核验适配版。
- **声音和画幅有边界**：新制作声音默认关闭，明确要求才设 `audio:true`；原样复现预设显式含原有音效，不自动沿用到别的片。`subtitle`不是对白字幕。模块有中英文可变字与按秒重映射切点，但新画幅仍须检查构图，不把改宽高称为已完成所有画幅的视觉适配。此版本输出独立不透明MP4，不是Alpha层或任意模型视频合成器。
- **正常回导**：完整解码/规格核对后 `aid_import_asset` → `aid_asset_path`，记录参数和摘要；需要接正文才走下一节，保持原片和已有定稿，不重复包装或变速。该脚本资源须通过独立安装或应用资源发布，不能放进纯文本知识包、编码成文档或假称知识升级已自动安装。

### Mac 专用可选模块：五套节目片头

另有用户提供的五套独立设计与共用`core.py`，按需复用，不替换AFTERGLOW、已批准片头或P01–P10。它们是可运行的本地模板，不是新增MCP工具；与AFTERGLOW共六个命名方案，不能把六套改称十套综艺组件。正式标题和短副文案来自当前影片，不固定“爱迪皮”测试文案。

| 风格键（`--style`） | 设计与适用方向 |
| --- | --- |
| `minimal` | 点、线、色块和两行文字接力；极简、文化访谈、品牌编辑，可选明暗主题 |
| `cinematic` | 引子、切黑、扫光、金属片名与识别落版；电影与戏剧标题 |
| `documentary` | 等高线过渡到日出多层山脉，再落主副标题；探索与自然纪实 |
| `acid` | 铬色抽象形、逐字贴纸、环字/胶囊/星标按拍点接力；当代娱乐与音乐 |
| `news` | 线框地球、斜切条带、标题板与节目/信息条；国际新闻感与时事栏目设计 |

当前独立资源位置为`~/.aid-partner/motion-kit/opus-titles/`。先检查宿主macOS、`render.py`、`README.md`、`templates/core.py`和所选模板、具备numpy/Pillow的Python、实际FFmpeg及模板用到的系统字体。缺项不自动下载或安装；Windows跳过此模块，其他制作仍可继续。知识包不携带Python源码/字体/执行器，不能仅因知识已更新就宣称其他用户已装运行资源。

Agent可用`python3 <模块>/render.py --list`发现五套，`--describe <风格键>`查看字段；这两个只读命令不渲染。正式调用由Agent准备本片JSON，再执行`python3 <模块>/render.py --style <键> --config <本片.json> --output <新的绝对路径.mp4> --ffmpeg <已核验路径> --mute`。`--still <秒数>`导出0≤t<5的PNG。用户无需填配置或手动合成；不得向`aid_generate`/`aid_packaging_render`传这些本地CLI字段。

这五套现为**固定1920×1080、30fps、5秒**，不透明MP4；与AFTERGLOW可配置时长/尺寸不同。其他画幅、时长、Alpha层及任意Logo/转场须另设计并验证，不静默拉伸/裁剪，也不承诺改参数即支持。中文/英文可变标题已支持，但仍检查本片实际字形与阅读窗口。原版`core.py`负责画布、字体、噪声、缓动与声音；统一适配入口负责安全参数、独立输出和编码失败，不直接执行上游`core.render`的覆盖写入。

声音默认关闭，本片明确要求才使用`--audio`（原代码合成音乐/音效，不是声音API）。正式配置必须提供`title`；未提供的日期、地点、坐标、演职员、直播状态和附加信息清空。`--demo`才保留原始演示文案，不能用于假造真实新闻、直播、上映日期、署名或精确地理事实。新闻地球与纪实地形是程序示意；ticker是包装信息，不授权对白字幕。酸性原版空色板会无限循环，适配器拒绝空palette，并将bpm限制为121–240以匹配5秒落版与音效；不把这一限制套到其他引擎。

只在用户本片已要求动效片头且该设计适合时选择；默认风格不触发制作。输出另存，按技术放行回导Partner，接正文时不要二次变速或再自动包装。原始用户文件保持只读，公开分发许可尚未确认，不将用户提供代码冒称开源；本地接入与用户审美批准、公共发布分开记录。

## 5. 时间轴与合成：最后一步才接到成片

**正文速度、动效时间和最终片长分别记录。**正文仍遵守主 Skill 已确认的合成速度规则；没有新的速度要求就不改变该默认。混合制作通常先完成正文剪辑及一次最终变速，再接入按最终交付时间设计的片头/叠层。这样锁定4秒的片头仍是4秒，不把已经按拍点渲染的动画再随整片变速；如果用户明确要求连片头一起变速，才使用同一映射并重算可读时间。

- **顺序插片**：片头 + 正文按已确认顺序用 `aid_compose`；中间母版传 `delivery:"intermediate"`。若片头已经渲染，最后 `aid_finalize_video` 省略包装或传 `packaging:{mode:"off"}`，不再自动生成一个标题。现有拼接跟随首片段比例且多片段按24fps处理；先让片头匹配正文，用户锁定其他帧率时选择已有且验证过的处理路径，不能承诺该接口保留全部源帧率。
- **图层叠加**：透明层需要真正的合成操作；`aid_compose` 仅按序拼接，不支持任意 Alpha overlay。内置模板可直接带原片渲染；外部层由已验证的本地工具合成后导入，不发明 `overlays` 参数。核对实际 Alpha/编码、边缘与底片，普通 H.264 MP4/棋盘图不能当透明层。
- **两镜转场**：明确 A 镜出点、B 镜入点及重叠量，用支持双输入的本地工具预合成；普通 `chapter` 卡只是过门，不等于两镜真正交叠。所需能力缺失时说明，不把硬拼当已完成转场，也不默认装新引擎。
- **片长**：顺序插片相加；转场按实际重叠量扣除；叠层不增加底片长度。纯顺序示例：正文母版24秒，确认1.2倍后20秒，再加锁定4秒片头，交付24秒。严格总长已锁定时在制作前分配片头额度，不能事后偷偷加长或裁掉正文；已锁内容无法容纳则明确冲突。
- **原声与规格**：保留获准保留的原声，静音片头不等于正文静音。拼接前核对尺寸、像素比、帧率、编码与音轨；遇到 HDR、多音轨或竖转横等既有工具限制，先说明并处理，不静默裁切、丢轨或色彩转换。

只有用户另行要求全片包装时，才在已经含片头的最终时间轴上安排其余指定事件，并显式排除重复片头。替换片头只重做受影响的本地渲染/合成；不得重新请求模型生成正文或覆盖旧成片。

## 6. 放行与交付

按[制作放行与修订](production-acceptance-and-revision.md)做必要技术检查：真实输出可解码、实际片长/尺寸/帧率/音轨符合计划、导入成功且任务 completed。检查新动效的代表阅读时点和受影响接缝（文字、资源、黑帧、重复片头、原声），不扩展为默认逐帧全片评分或循环重做；用户只要方案时不声称已渲染。交付最终成片及有用的可编辑工程/独立片头，未验证事项如实说明，不让用户再手动拼接。
