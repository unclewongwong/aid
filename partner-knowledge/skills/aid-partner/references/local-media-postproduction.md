# 本地后期与交付：按真实素材选择处理方式

字幕、标题和文字叠层的选字须执行[字体商用许可](font-commercial-licensing.md)：许可覆盖本次商业用途，核对实际文件、字重及回退字体；libass 成功烧录不等于字体授权已通过。

已有音视频需要裁切、拼接、抽帧、改画幅、声音处理或导出时读取。这里补充媒体处理决策；创作意图、逐字对白和已选素材仍来自本片，放行范围沿用[制作放行](production-acceptance-and-revision.md)。单纯写剧本或调用生成模型无需加载本页。

本页融合 ffmpeg-skill 的素材探测、少重编码和结果验证思路；来源与 MIT 声明见[许可说明](local-media-postproduction-notices.md)。这是知识指南，没有安装其 Python 脚本、42个工具、平台模板或 MCP，也没有给 Partner 增加参数。

## 1. 从实际文件得到处理依据

使用当前宿主已有的媒体工具；Partner 素材先经 `aid_asset_path` 取得真实路径。需要本地 FFmpeg 时确认可执行文件可用，不能把本机终端版本等同于 App 内置版本。仅在要使用特定编码器、滤镜或出现能力错误时检查对应能力，不为简单抽帧做全环境扫描或安装软件。

可用 `ffprobe -v error -show_format -show_streams -of json "源文件"` 读取初始信息。一次取得规划所需的事实，可信执行结果已带输出探测时不重复读取未变化文件：

- 视频：编码、像素格式、编码宽高、旋转/显示矩阵、SAR/DAR、帧率与时间基、起始时间和实际时长。横屏容器可能靠元数据竖向显示，非方形像素也会改变显示比例。
- 帧率：标称与平均帧率不同只是 VFR 线索；精确剪辑、同步或出现异常时检查帧/包时间戳。不能仅凭两个数相同断言恒定帧率，也不把所有素材自动改成30fps。
- 颜色：色域、传递函数、矩阵、位深及存在的HDR侧数据。BT.2020色域标签本身不证明HDR；未知标签记录未知。HDR转SDR需要真实色调映射，不能只改标签或转8位就称正确转换。
- 声音：所有音轨的索引、语言/默认标记、声道布局、采样率、起始偏移和时长；分清无音轨、存在静音轨及有效声音。无字幕流不证明画面没有烧录字幕。

多片段操作开始前集中核对输入是否齐全、可读取、属于被采用版本且顺序正确；缺段先报告具体条目，不默默跳过或按文件名猜顺序。把源路径/版本、采用区间和目标规格记入已有项目台账，复杂变换记录参数与源到成片的时间映射；简单抽帧不另建项目或庞大编辑工程。

## 2. 选择最少且能满足要求的处理

| 任务 | 决策与实际核对 |
| --- | --- |
| 换容器、取出或替换声音 | 容器支持源编码且不改画面时优先复制视频码流；明确选择/移除哪些轨，不默认只留第一轨。封装成功不证明同步正确。 |
| 普通裁切与帧级切点 | 码流复制通常受关键帧/音频包边界影响；可以用于容许该误差的片段。锁定切点、嘴型、对白尾字或动作落点时用能满足精度的解码裁切/必要重编码，并量实际入出点及首尾可见帧。不能把 `-c copy` 或MP4编辑列表当成跨播放器的帧级保证。 |
| 拼接多段 | 先比较编码参数、显示尺寸、像素格式/颜色、时间基/帧率和音轨布局。仅扩展名一致不够；兼容时才尝试复制拼接，需转换时以交付目标统一必要参数，不机械跟第一段。缺音轨按已定声场安排静音或配音，不替整片丢掉声音。 |
| 画幅与尺寸 | 等比缩放后选择补边或有依据的裁切。裁切锚点来自人物/产品在画面中的实际位置和运动，不能只在首帧居中就判全段安全；不得横竖拉伸。字幕/图形按最终显示画幅排版。 |
| 时长与变速 | 裁短会丢内容，变速会改表演；按本片已定方式执行，不按倍数阈值自动二选一。视频时间戳与音频时长一起处理，保音高不等于对白仍易懂。已确认的整片1.2倍只在原速合成母版上做一次，记录完成状态，避免每段或后续导出再加速。 |
| 混音与响度 | 声音内容/轨道先确定，再按用户或实际交付规格做测量和必要调整。需要响度归一时可先测量再处理，并复测编码后响度/真峰值；不把-14 LUFS或某平台预设当全片默认，不把环境静默、呼吸或戏剧停顿自动删除/增响。 |
| 字幕、Logo、动态图形 | 沿既有R3/R4/R5授权；平台名称、导出请求和检测到人声都不自动授权字幕/包装。已有逐字文本不因排版困难改写；调整字号/换行/位置，并检查最终裁切后的遮挡和可读性。 |
| 封面与单帧 | 从原视频取不同表情/动作阶段候选，实看眼睛、嘴形、运动模糊和构图；记录来源版本和时间点。用于网站/卡片时再看真实容器的裁切，帧在原尺寸好看不代表窄横幅中完整。 |

只调整声音时尽量保留视频码流；需多个画面处理时合理合并，减少有损中间转码。时间轴变换先确定，再布局文字/图形，最后按交付规格编码。转场、静音剪除、自动高光、LUT、补帧、超分和平台模板均不作为拼接/导出的隐含步骤。平台要求须按当前实际目标核验，不能依赖写死的历史限制。

## 3. 执行与验收分开

复杂/长耗时处理先检查参数、输入输出与预期变化；若工具有预演模式，确认它是真实执行计划，不能把预演输出当产物。直接调用现有FFmpeg时使用参数数组或正确引用路径；运行异常先定位参数/滤镜/素材原因，不把完整脚本反复重跑。原始素材保留，输出新文件，临时文件和旧成品不互相覆盖。

检查以本次修改影响为边界：

- **技术事实**：执行退出正常、输出存在且可解码；实际时长、显示尺寸、帧率、颜色信息、音轨及其时间关系符合交付要求。毫秒/帧误差按素材时间基与本次要求说明，不拿统一零误差或一个通用阈值掩盖差异。
- **修改是否落地**：裁切看边界前后，拼接看接缝及是否重复，换声核对旧轨移除/新轨位置，改画幅/颜色/叠层查看相应画面。验证本次编辑效果不扩展为全片剧情/口型/审美自动质检；抽帧只说明看过的时刻，音轨时长一致不证明口型同步。
- **创作判断**：平台检查中的静音、黑场、低帧率、缺字幕等提示不一定是错误；结合用户要求和片中用途处理。没有自动审美评分，不为消掉WARN擅自裁内容、增响、加字幕或付费重生。设备能力缺失和素材失败分开报告。

已有有效检查、文件未变且本轮未影响的项目可以复用。发现错误只修相关层，验证受影响部分，不循环进行全量检查。交付报告包含实际文件、关键规格、已验证范围和仍存在的限制；不强制特殊报告前缀，也不以命令成功替代成片验收。

属于 Partner 项目的本地成片，仍经 `aid_import_asset` 导入，再按主Skill的单素材 `aid_finalize_video` 方式登记同项目最终交付，避免再次拼接、加速或添加包装。普通独立文件处理不为了登记而创建虚构项目。

## 4. 典型取舍

- “只把口播画面换成新版，声音保持”：先核对新版时长和动作时序是否适配旧音频，明确移除新版原声，再复用锁定音频；音频文件相同不能证明新嘴型吻合。
- “把手机录屏和电影镜头剪成一条”：先核对旋转、VFR、色彩及声音起点，按已定交付规格统一必要差异；不把手机HDR随意改标签，也不默认补转场。
- “这张官网封面不好看，换一帧”：只抽帧、挑表情并检查实际展示裁切；不重生人物、不重编码整条视频、不改片名和已确认数量。
