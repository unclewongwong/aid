# 优秀案例迁移与 H3 提示词编译

用于把剧本、逐秒视听时间线或分镜写成实际镜头提示词。目标不是引用、拼接或仿写某一条案例，而是识别案例解决了什么导演问题，把可迁移的方法改造成当前影片自己的动作、表演、摄影与声音。

## 1. 先为当前镜头建立难点指纹

检索前先从当前剧本和分镜提取本镜事实，不用“电影感、节奏快、动作精彩”这类泛词代替：

- 本镜的戏剧功能、进入状态、必须发生的状态变化和退出状态。
- 实际目标模型、媒介、生成模式、时长、画幅、参考素材数量及各自职责。
- 主体数量、身份锚点、动作类型、接触关系、连续性风险和环境状态。
- 表情或情绪从什么事实触发，眼神、呼吸、重心、手脚和口部怎样变化。
- 摄影机起位、主任务、可通行路径、速度曲线、制动与落点。
- 声音来源、关键落拍，以及特效是否由接触、气流、光源或环境变化产生。

以这组难点调用 `aid_prompt_guide`，brief 必须写当前镜头的具体内容和难点。连续镜头只有在题材、模型、输入结构、动作密度和摄影方法相同的情况下才能共用一次检索；任一项改变就重新检索。不能只用全片片名或“武侠短片”做一次泛搜，然后把同一方法套满全片。

## 2. 案例只提供方法，不提供本片内容

读到候选案例后，在内部建立“方法迁移单”，至少回答：

| 项目 | 必须写清 |
| --- | --- |
| 案例解决的问题 | 例如双人攻防看不清、表情变化太静、运镜失去空间方向、特效与命中脱节 |
| 有效写法 | 案例如何写起点、触发、路径、速度、接触、反应、落点及声画结果 |
| 当前镜头等价物 | 换成当前角色的目标、身体能力、道具、空间和情绪后，具体是什么 |
| 落入位置 | 进入当前实际 prompt 的哪一时间段、哪一拍或哪一个 H3 Shot |
| 不迁移内容 | 案例的人物、剧情、品牌、固定时长、招式组合、镜头数量、API 字段或不适合本片的风格 |

案例启发必须能在最终 prompt 中找到明确落点。只调用检索、复述案例标题、罗列“参考了运镜/节奏”，却没有把方法变成当前镜头的具体时间化指令，不算完成学习。不得为证明使用案例而强塞不适合当前剧情的动作、镜头或特效。

## 3. 把好写法改造成当前影片

迁移时保留的是描述规律，不是表面词句：

- **动作**：写“谁因什么先动 → 身体哪一部分沿什么方向运动 → 对方怎样防守或回避 → 接触/落空后产生什么结果 → 双方进入什么新位置”，不复制案例的一整套招式。
- **表情**：写触发事实和变化过程，例如视线先锁住来拳、眼睑收紧、下颌咬住，命中落空后呼吸短促、眉眼由确定转为警觉；不只写“愤怒、震惊、冷酷”。只选能讲清本拍的关键面部和身体信号，不堆满所有器官。
- **摄影机**：写起位、相对主体的高度/距离、直线或弧线路径、运动方向、加速点、巡航段、制动开始、零速度落点和构图结果。案例用环绕，不代表本片也要环绕；先判断当前动作的接触点、位移方向和新信息需要怎样被看见。
- **节奏**：按当前情节确定 BPM、每拍秒数、严格或松弛服从和关键拍，不继承案例的 BPM 或固定秒数。高密度不是同一秒并发更多动作，而是更短的因果单元和更少的无功能等待。
- **声音与特效**：写清声源或视觉效果的物理触发、方向、强弱、持续和衰减。冲击波、火星、气刃、尘浪等必须在拳脚接触、空气压力或环境破坏之后出现，不能脱离动作自行爆发。

若当前时长、模型容量或参考素材不足以承载案例的复杂度，应拆分、删减或降低动作密度。不能把一个30秒十段动作案例压进10秒，也不能用更长文字假装模型拥有更多时间和控制能力。

## 4. H3 优先，跨模型只迁移可兼容层

目标是 H3 时，优先检索 H3 原生案例，并用 H3 原生结构完成最终编译。其他模型案例只能贡献可迁移的方法：

| 案例来源 | 对 H3 可迁移内容 | 不能直接继承 |
| --- | --- | --- |
| H3 原生视频 | Shot 时序、Picture 绑定、动作/摄影/声音的共同时间线、对白标签 | 案例题材、人物、固定时长、实际素材编号 |
| 其他视频模型 | 动作因果、空间连续、表演、运镜动力学、声音设计 | 该模型专属格式、参数、素材标签与能力假设 |
| SD/静态生图 | 主体外观、构图、镜头视角、光线、色板、材质和单一时刻的可见状态 | H3 的时间推进、动作阶段、运镜路径、对白、声音和多 Shot 结构 |

本项目采用不对称兼容原则：H3 提示词中的视觉约束可以抽取某一个时间状态，改写成 SD 静态画面；SD 提示词不能默认直接作为 H3 视频提示词。SD 案例缺失的时间、动作、摄影机、声音、参考图职责和结束状态必须重新导演和补齐。检索时 `modelFamily` 传真实目标模型；不能为了获得更多案例把 H3 任务伪报成 SD。

## 5. 编译为 H3 的实际请求

H3 最终 prompt 使用实际工作流支持的素材标签，并保持下列骨架：

```text
integrated_multimodal_description: [Shot 1] ... [Shot 2] At 00:03.000 ...

overall_soundscape: ...

non_diegetic_music: ...
```

编译顺序：

1. 在正文开头声明本段真正恒定的身份、服装、空间、光线和连续性锚点；不反复堆“绝不改变”。
2. 按真实切点组织 `[Shot N]`。同镜内部的多个动作阶段、分镜状态和运镜变化仍在同一个 Shot 内按时间/拍点连续描述。
3. 每个时间段写出人物动作、对手/环境反应、表情、摄影机和声音的并行变化；所有变化都有起点、触发、路径/方向、速度和到达状态。
4. Picture 只绑定实际已上传素材，逐张写清身份、首帧、道具、环境或目标状态职责；不存在的图号不进入文本。
5. `overall_soundscape` 只写可听的环境、动作、对白及声源，不重复视觉形容词；`non_diegetic_music` 写配乐及节拍，明确无音乐时写“无”。
6. 负面约束只保留当前模型最可能破坏且正向过程仍无法完全排除的少量问题，不能用长禁令替代动作、表情和运镜正文。

## 6. 双人打斗案例的可迁移规律

处理双人或多人动作时，可从优秀打斗案例迁移以下导演规律，但招式、角色和空间按当前剧本重新设计：

- 先给每名角色独立的力量、速度、距离、策略、重心和效果签名，保证不是换皮对打。
- 每轮交换都能读成“进攻 → 防守/闪避 → 反制 → 结果/新位置”，不写双方同时乱挥。
- 摄影机优先跟随接触点、被击退方向或下一处空间目标；重击可短促定向震动，但主体与轴线必须可读。
- 同一环境的裂纹、断柱、尘雾、火源和道具损坏持续累积，不在下一拍复原；空间变化由人物位移和破坏造成。
- 特效先有物理触发，再有局部出现、扩散和衰减；不同角色的效果服务其动作特性，不做无来源彩色对波。
- 攻防密度升高时仍保留关键接触、受力和恢复动作。模型无法清楚表现“十几次交换”时，选择少量决定性动作，不靠数量词掩盖缺乏编排。
- 表情随战术信息变化：预判、受压、判断落空、抓住空隙、受击恢复和终局意志分别有可观察信号，不让角色全程只保持同一怒脸或冷脸。

## 7. 保存或生成前的迁移落地门禁

逐镜检查：

- 当前镜头是否用自己的角色、目标、空间与时长重新设计，而不是换名复刻案例。
- 每项采用的方法是否已落入实际 prompt 的明确秒段、拍点或 Shot。
- 动作是否有起因、过程、对方响应、物理结果和新状态。
- 表情是否由事实触发并经历可见变化，而非静态形容词。
- 摄影机是否有完整路径和速度曲线，能到达指定构图且不穿越实体、不乱跳轴。
- 声音、特效和环境变化是否与可见动作同源并持续到合理结束。
- H3 任务是否保持 H3 结构；来自 SD 的内容是否只用于可兼容的静态视觉层。
- 删除案例标题和迁移说明后，实际 prompt 是否仍能独立拍出当前故事。

任一项失败就回到提示词阶段修改。检索数量、相似度分数、引用案例名称或更长提示词都不能替代这道检查。
