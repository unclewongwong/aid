# 制作成果交接：从完整故事到可提交提示词

用于首次建立整片计划、已有成果交接、流程断裂或局部返修。它补充主Skill的A–H，不建立第二套剧作/摄影规则；按当前阶段读[故事](story-dramaturgy.md)、[导演表达](director-storytelling-and-shot-causality.md)、[逐秒视听](whole-film-second-by-second.md)、[分段](storyboard-segment-generation.md)和[编译](prompt-case-transfer-and-h3-compilation.md)。用户只要方案不调用生成，已有锁定内容不重写；执行仍服从主Skill的授权、字幕/包装/声音与能力边界。

## 1. 先选任务深度，成果不是必填表

| 本次请求 | 这次应交付 | 不应追加 |
| --- | --- | --- |
| “帮我写个故事/剧本” | 本次所需的完整正文与对白；必要的B/C用于构思和复核 | 不交几张卡冒充剧本，不擅自生图/视频 |
| “按这份已定剧本设计分镜” | 保留正文与锁定对白，补D/E/F；需提示词再做G/H | 不重写B/C以迎合新模板，不改变人物/结尾 |
| “用这些现有镜头加指定片头” | 本片文案、美术、片头最终时长与接入点，再定向渲染合成 | 不重跑故事/模型正文，不自动加全片包装和声音 |
| “生成这张产品图” | 明确产品/素材/画幅/授权，核对实际模式，再写对应静态prompt | 不强套角色冲突、逐秒表和视频分段 |
| “制作一段口播” | 逐字讲述正文、音色/路线，按字数估约20秒一段，再按实际录音配画面 | 不编成戏剧反转，不把30秒当通用硬上限 |
| “修第3镜的持物错误” | 先定位真实版本/时段；检查该镜和受影响接缝 | 不推翻已批准镜头、全片打分或改供应商 |

A–H可写成自然段、合并表或项目现有结构。字段名帮助找回信息，不要求给用户展示八张表、逐项审批或先选模板编号。已有成果可直接复用，不为了补形式重新创作；真正影响执行的缺项才补。

## 2. 最小成果结构与读取依赖

每层持续保留三件东西：本次锁定要求、当前有效完整正文/用户素材、相关成果与版本。不是只读取上一张表；叙事以外的作品按说明/观察/过程/品牌任务设计，不强造主角与反派。

| 成果 | 最小可用内容 | 向下一层交什么 |
| --- | --- | --- |
| A 交付约定 | 起点、片型、标准/交付时长含义、画幅、语言、声音/字幕/片头/包装要求、授权、锁定项、交付深度；有生成需求再核实际路线 | 本次允许做什么、不能改什么、何时算完成 |
| B 故事契约与正文 | 人物的目标/阻碍/代价、观看承诺、完整起因—经过—选择—后果；逐字对白和必要场景 | 正文是事实来源，卡片只帮助把握主线 |
| C 拍点 | 拍号、先前条件、行动/选择、即时结果、改变的状态、带出的下一步；必要时列时长 | 哪些变化有因果，哪些停留有表达作用 |
| D 导演表达 | 对应拍号、观众/人物知情、观看任务、直接/反应/画外/痕迹等表达、视点与切/不切理由 | 怎样让观众看到、听到并感受正文，不只给名词配图 |
| E 逐秒视听 | 标准速度全片区间，动作/表演/摄影/声音的起止与落点、阅读/呼吸停留及节奏映射 | 覆盖全部所需时间；计划秒点不是模型执行保证 |
| F 视觉分镜 | 唯一镜号、全片入出点/镜长、拍号、景别/机位/视线、镜内发展、对白、进出状态；关键画面另有K号/目标时刻 | 镜号与关键画面分开，同镜多图不变多镜 |
| G 生成安排 | 段号、覆盖的F镜号及全片区间、合法任务时长、模式/真实素材角色、段首段末状态、依赖与续接方法 | 把已有设计编排成任务，不重新按容量编故事 |
| H 实际prompt | 对应G段号、局部时间、自包含初态→动作/摄影/声音→终态、真实素材编号及必要限制 | 模型必须知道的内容进入实际请求，不只存在story |

按[故事先行](story-first-and-series-continuity.md)保存完整正文。A–G及它们的映射写入项目`story`或已有制作台账；`shots`只使用真实支持的`id/prompt/dialogue/duration/references`。已有镜号保留，不把A–H或G/K号当新的API字段；项目实际存储结构与视觉镜头、生成任务分别记录。

三种时间不得混淆：全片标准速度时间、段内请求时间、最终交付时间。全片`[10,20)`放入10秒任务时，段内为`[0,10)`；相邻区间按`[起点,终点)`衔接。只有纯恒速正文才可统一除倍率，独立锁时长片头在该步骤之后按最终秒数接入。

## 3. 连贯示范：沿用《雨夜送粥》，不另起炉灶

完整正文、具体表演/镜位、全部对白和两段H3成稿在[端到端示例](worked-example-short-film.md)。以下只补各成果如何互相定位；正式制作不能只复制本页摘要。它是假设9:16写实、标准速度20秒、原生同期声，所选工作流明确接受10秒/首帧及两张辅助参考；没有实际素材ID、没有执行生成，不能把假设当当前客户端能力。

### A/B：交付约定与故事

- A：当前为制作方法示范，不提交生成；20秒指标准速度正文，字幕/包装/片头/配乐未要求。若实际项目沿用一次1.2倍，交付约16.67秒；若用户锁定其他含义先协调，不自行加长已定故事。
- B：外卖员阿杰想送完暴雨中的最后一单，停运电梯增加阻力，他仍爬楼送粥；以为老人会介意迟到，却发现她记住了自己的生日。跟随理由是他的具体付出；结尾温暖来自此前行动与被记住，而不是随便加入一个反转。
- 完整正文与逐字对白仍读示例第1节及第5/6节；本段B不是可替代正文的交付。

### C：变化怎样接力

| 拍号/标准区间 | 先前条件→行动→结果 | 状态与下一步 |
| --- | --- | --- |
| C01 / 0–5秒 | 暴雨刹停，母亲来电提醒生日；他仍看向要送达的楼门 | 观众先知道生日，送单与收工形成具体取舍 |
| C02 / 5–10秒 | 他回答送完再回，收手机；发现电梯停运，抱袋爬楼 | 坚持目标但付出体力和时间，承接到达门口 |
| C03 / 10–13.33秒 | 门开；他喘息着道歉，仍抱保温袋 | 观众与他都等待老人接粥/回应，暂缓揭示 |
| C04 / 13.33–16.67秒 | 老人没有接袋，转身端出蛋糕并说上周记下生日 | 收件人的意图被重新理解，兑现C01信息 |
| C05 / 16.67–20秒 | 他愣住、低头笑、抹去雨水 | 让观众读清被记住的感受；安静反应有功能，不再添冲突 |

### D：同一事实，先选观看任务

| 对应拍号 | 观众/角色知情与表达选择 | 为什么这样拍 |
| --- | --- | --- |
| C01–C02 | 通过手机外放先建立生日；动作与上楼过程保持可读 | 不依赖小屏幕文字，不用字幕补设定 |
| C03–C04 | 留在阿杰一侧看门内，先见“不接袋”，再见蛋糕 | 给等待与揭示先后顺序，不提前在背景露出答案 |
| C05 | 反打阿杰的近景，保留手中袋子与动作状态 | 新信息的后果在听者身上，不用解释性旁白替代反应 |

这些是本例的选择，不意味着所有作品都限知、必须反打或每镜都延迟揭示。

### E/F/G：镜头和任务不是一回事

| F镜号 | 全片标准区间 | 覆盖C拍与事件 | 所属G任务/段内时间 |
| --- | --- | --- | --- |
| S01 | 0–7.50 | C01与C02前段：刹车、电话、决定继续 | G01 / 0–7.50 |
| S02 | 7.50–10.00 | C02后段：读停运状态、冲楼梯 | G01 / 7.50–10.00 |
| S03 | 10.00–14.17 | C03和C04前段：开门、道歉、不接袋、托住蛋糕 | G02 / 0–4.17 |
| S04 | 14.17–16.67 | C04后段：端出蛋糕与老人对白 | G02 / 4.17–6.67 |
| S05 | 16.67–20.00 | C05：反应和收口 | G02 / 6.67–10.00 |

具体E秒表仍见原示例第3节，不把上表粗区间冒称全部逐秒细节。G01→G02是故事已有的真切镜：楼梯到门口；不是把楼梯末帧强行变成门前首帧。后段继承湿衣、喘息、保温袋与送达目标。若同镜超容量续接，必须改用该情况下真实可用末帧与运动趋势，不照抄此切镜方案。

G01假设首帧是楼门口构图，辅助图分别负责阿杰身份与楼道；G02首帧是铁门刚开，辅助图负责阿杰和老人身份。实际素材先导入，再按预览返回的顺序编号；表里的职责不保证目标接口支持多图控制。

### H：把映射落到真正成稿

读原示例第5/6节完整prompt：G02从局部0秒开始，不接着写全片10秒；原生Picture工作流才沿用`<Picture N>`。只在真实切镜使用新的`[Shot N]`；同镜的K图状态放在同一Shot里。已确认的其他供应商语法与素材键分别编译，不能混用。

提交前对着G检查H：段长和合法时长一致；五个镜头覆盖无漏、无重复；对白逐字与说话人保持；所有实际图角色被使用；进入/退出状态连得上；声音按本片要求处理。工具不支持精确切点时，时间指令只是设计目标，不能承诺模型逐帧执行。

## 4. “差→好”应改在哪一层

- **剧本问题**：差：“送餐员很辛苦，老人很感动，温暖收尾。”好：补齐电梯阻力、仍选择爬楼、老人记住生日的证据与阿杰的具体反应。先改B/C，不靠慢推和暖色替代故事。
- **导演问题**：差：“老人说生日快乐，切蛋糕，再拍感动脸。”好：先决定观众和阿杰何时知道蛋糕，安排不接袋→揭示→反应；沿用锁定对白。改D/E，不自动添加新台词。
- **提示词问题**：差：“按剧本继续，人物一致，感动。”好：把本段湿衣/抱袋/门状态、蛋糕进入的过程、机位与实际对白时段写进H；身份参考与首帧角色分开。不能只往story补一句“保持连续”。
- **接缝问题**：差：“每段结束都停住，下一段重新亮相。”好：明确任务边界是真切镜还是同镜续接，只继承所需状态、不重演已完成动作；改G/H和受影响入出点，不重做无关镜头。

## 5. 返修和检查的最小范围

先绑定用户反馈对应的真实版本和采用区间；再判断改动影响哪一层：

- 只改标题配色：检查本地素材、文字可读与接入点，通常不改故事或请求正文视频。
- 改一句锁定对白：取得对应修订范围，重新估该段声音时长/表演及受影响时间线；保留其他台词与旧成品。
- 改角色图：定位哪些任务实际引用该版本，以及相邻镜头的身份连续；不能把旧输出自动当成已采用新图。
- 时间线变化：更新全片/段内/交付映射、受影响生成边界与已有图形事件，不只替换表格数字。

输入自检用于消除已知冲突，不证明生成质量。按[制作放行](production-acceptance-and-revision.md)区分技术通过、用户确认与未检查内容；不新增自动审美评分、付费小样、无限重生或主观公式门禁。
