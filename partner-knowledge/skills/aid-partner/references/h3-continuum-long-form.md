# H3 Continuum：连续长镜头、分块提示词与续写

用于明确指定 ComfyUI-H3-Continuum，或需要长镜头、连续表演、多段音画衔接、保留已满意部分再续写的任务。它补充[成段生成](storyboard-segment-generation.md)与[H3 编译](prompt-case-transfer-and-h3-compilation.md)，不改变完整故事先行、逐镜设计、真实素材与已锁定对白。按当前难点读对应小节，不要求每次填完整表。

方法来自独立社区项目，非 MiniMax 官方扩展。核对基线为上游提交 `308653cff108061a94381cef446fef985384b214`（包版本 3.10.2，当前工作流 V3.9）；来源与许可见[说明](h3-continuum-notices.md)。节点包版本、工作流版本、模型和 Partner 应用版本分别记录，不能用一个“最新版”代替。

## 1. 先分清创作方法与实际执行能力

| 层 | 可以怎么用 | 使用条件 |
| --- | --- | --- |
| 连续导演方法 | 规划全片能量与行动，逐段交接身体、道具、摄影机和声音状态；只追加新段，保留已接受文本 | 所有适用的 H3/其他模型创作均可吸收，按目标格式重新编译 |
| Continuum 提示词路由 | 用 Fixed / List / Timeline 选取每个逻辑块的正文，再交给 H3 | 所选工作流确实接入对应版本解析器；普通 H3 API 不自动识别 `[Chunk N]` |
| 原生音画状态续接与 Take 复用 | 由实际节点保存视频/音频上下文、校验旧状态并采样后续 | 已安装的 Continuum、匹配工作流、持久化 Run/Take 与当前工具可操作输入都已核实 |

制作前按主 Skill R10 查看实际 `aid_status`、`aid_workflows` 与输入；有适用接口时用只读请求预览核对映射。纯写稿不要求启动服务。如果只有普通 H3 或首帧路线，照样应用导演交接，但按原格式交付；不能把 `chunks`、`run_uuid`、`exact_total_duration`、`@R1` 等凭空加入 `aid_generate`，也不能冒称已有潜变量续接。用户锁定 Continuum 而接口未接入时，保留可用提示词和明确缺项，不静默换路线。

知识融合本身不安装节点、模型、加速器，不重启 ComfyUI，不改默认采样或音轨。Spectrum、Sage、Sol、Turbo、Second Pass 都须按实际版本及已有授权单独核验；上游提供模板不代表本机兼容，Second Pass 不默认开启超分。只要方案/提示词就不发生成任务。

## 2. 连续表演：从上一段的余势启动下一段

全片先定开端、发展、能量变化、关键落点和结尾，再把已成立的行动放进合法生成区间。块不是独立小故事，不让每块重新站定、重新开场、重新起配乐或各自收尾。实际镜头切换依剧情，生成块切换依容量，两者分开。

每个边界只记录能唯一说明交接的最少事实：

`前段到达状态 → 仍在继续的运动/声音 → 后段由此启动的动作`

- 人物：位置、朝向、支撑脚/手、重心、躯干转向、持物与空手、眼神，动作做到哪个阶段。
- 运动：行进与旋转方向、剩余速度、蓄力、刚发生的落地或减速；反向前先有承重、制动与转向过程。
- 摄影：机位在人物哪侧，景别、焦段意图、移动方向与速度趋势、焦点及遮挡；不在新块自动回正面。
- 声音：谁正说哪一句、词句是否完成、环境声/旋律/节奏延续到哪里；实际源音频和计划声音分开记录。

舞蹈、武打或持物操作尤其要让“落点—余势—发力”连起来。例如上一段停在左脚承重、右脚向画面右侧迈出的途中，后段接右脚落地并转移重心，再完成转向；不能先恢复双脚并拢再重演这一步。跳跃要有落地，低位动作要经支撑起身，旋转要保留轴与方向。动作仍按[动作七槽](action-seven-slot-precision.md)写；镜头给支撑脚、手和道具足够可读空间，不固定每块招式数或强迫全身景别。

新写的第二块以后，在正文开头用“承接第 N 块：……”加具体继承状态；需要英文时可写 `Continuation of Chunk N.`。这只是语义提示，不是采样命令或无缝保证。只有看过被采用输出才能称为“实际末态”；否则标为计划交接。已有生成块不为补一句承接语而改写。

共享描述只放真正恒定的身份、服装、环境和光线，不逐块加码高饱和、高对比、锐利、油亮等形容词。出现累积变色或质感漂移时分别定位文字、路由、模型/运行条件；克制文字不是已验证的漂移修复。保留用户选定风格，不擅自降采样、改 seed 或换模型。

## 3. 三层时间和两种编号

先在项目 `story` 保留：全片区间、逻辑块号与长度、镜号、正文局部时间，以及运行端实际物理分组。记录是交接信息，不是新增 API 字段。

- `Chunks` 是目标总块数。例如原来 2 块、每块 6 秒，延长为 3 块才是增加一块，名义总长 18 秒；填写 1 不代表“再加一块”。秒数和块数来自实际能力，不照搬示例或强制 5 秒。
- 全片/外层 Timeline 时间用于分派正文；块内动作与 H3 Shot 切点按该次实际模型输入的局部时间编译。解析器不会自动把正文里的全片秒数减去块起点。
- `[Chunk N]` 是 Continuum 逻辑路由，`[Shot N]` 是正文内真实镜头。换块不自动切镜；同镜多图仍是一个 Shot。首个 Shot 不带时间码，后续真实切点才写递增的 `At MM:SS.mmm`。
- 部分首尾帧配置会把末尾两个逻辑块合成一个物理采样/复审单元。查看实际计划与报告，不承诺每块都能独立采样或重做；不用“逻辑块数=GPU 调用数”估算时间和费用。
- 名义时长不是实测成片时长。帧量化、末组处理与 Finalize 影响最终输出，按真实文件核对；不把 Character Swap 的帧数公式或其他节点的重叠帧默认套到 Continuum。

## 4. 可靠路由：标题独占行，正文完整覆盖

以下规则适用于已核对的 Continuum 解析器，不能迁移成通用 H3 API 语法。

| 格式 | 适合什么 | 要防止什么 |
| --- | --- | --- |
| Fixed | 持续状态或不需要不同台词/阶段的重复活动 | 整段文本会发给每块；修改它会影响全部旧块 |
| Timeline | 有先后行动、对白、不同参考绑定的分块进程 | 优先显式选择 Timeline；每个 `[Chunk N]` 独占一行，下一行开始正文，1 到目标块数各覆盖一次 |
| 时间区间 Timeline | 需要和已知块边界对齐的时间表 | `[0-6s]` 等也独占行；一块只选重叠最大的一个区间，等长重叠取较早者，不会自动拼出多个子阶段 |
| List | 已有列表或明确要保持列表写法 | 独占行 `---` 分隔，或字符串 JSON 数组；不足会重复末项，多余会忽略，不依赖这种回退 |

不要写 `[Chunk 1] 动作正文`、`[0-6s] 动作正文`，不要把 Shot 当外层路由，也不要混用 Timeline 与 List 分隔。当前解析器遇到错误可能回退 Fixed 并给警告；Auto 甚至可能将整份畸形脚本直接判为 Fixed。执行前检查实际选中正文、格式与警告，不能因请求没报错就认为路由正确。知识验收只验证过解析行为，不等于模型服从性。

时间区间例：一个 10 秒块配 `[0-5s]` 和 `[5-10s]` 两段，等长重叠会只选第一段。正确做法是用一个 `[Chunk 1]`，在正文内描述 0–5 秒与 5–10 秒两阶段。漏块可能沿用前块或最早有效块，所以生成前必须补齐，不让模型重复前一句对白。

首个标题之前的文本是共享前言，会进入每块。只放恒定且处处有效的条件；某块专用的角色/图号/事件写进该块。独立请求需要自包含，不能删掉必要设定；Continuum 内部也不把三字段或六字段省成一句“继续之前”。基础模式沿用 H3 三字段，复杂 Ref2VA 按实际模式采用 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。正文默认中文，结构标签与逐字对白保留。

## 5. 参考图职责与 V3.9 固定槽位

先确认每张图实际内容、连接、所选块，以及它提供身份、衣服、道具、环境还是风格。不能从用户附件顺序猜节点槽位，不能编造没看过的图像细节。

在已核实的 V3.9 Reference Images 中，`@R1`–`@R9` 指固定插槽；槽 2 空着不会把槽 4 改成槽 3。每块只引用已连接且被选中的槽位，写“`@R4` 中的女子”而非“`@R4` 行走”。它指图源，不是人物。实际 `<Picture N>` 会受首尾帧和当前物理组中的参考影响，交给对应节点解析，并对照 Reference Plan；普通 H3 仍使用当前已确认的 Picture/Image 编号。

`<Subject N>` 是持续主体，和 R/Picture 编号各自独立；一人可有多张图，一张图也可只提供背包。明确身份与属性归属，例如人物取自 R1、背包取自 R4、替换原背包而非再生一个；保留脸/服装但改变姿态时写出从可见原姿态到目标姿态的动作。retention 标记只表达意图，不是硬遮罩。

新增加的块不保证自动继承 Per chunk 勾选。检查图仍连接且新块确已选择。没选择某张图不等于该人物消失；继承画面可能继续带着她，必须写具体离场、遮挡或视点变化。无效 `@R` 可能仅警告并原样保留，不能当作已绑定。配置表只是设置；修改配置后，先前的“runtime verified”报告不能冒充当前实测。

首帧、尾帧、普通参考与实际上一段末帧分开：续接不每块回到原首帧，目标尾帧只在相应终段收敛。末尾合并组要求有效参考集合一致时，不擅自改勾选绕过冲突；先核对分组/能力，再在原授权范围内调整方案。九槽是此节点的能力，不代表其他供应商、模式或 Partner 适配器支持九图。

## 6. 声音路径决定怎样衔接

| 路径 | 实际职责 | 提示词应做什么 |
| --- | --- | --- |
| Reference Audio | 条件参考，如音色与表达；不复制源波形 | 核对真实 `<Audio N>` 映射，逐句指定说话人；Subject/Audio 编号不自动相同 |
| Driving Audio | 已接线的源音频驱动画面，并由对应 Finalize 路径作为最终音轨 | 保留原音轨，写动作与真实音频事件的关系；不要另写矛盾的新台词或要求生成另一首音乐 |
| Audio Continuity | 把先前生成音频上下文交给后块 | 延续当前说话/声场/音乐状态；它不是导入外部录音 |
| 仅视频参考 | 视觉信息 | 没接音频不能声称原视频声音会自动保留 |

文字不能接线，也不能开启上述能力。按[音频参考](audio-reference-generation.md)核对所选路线；保留原语言与逐字对白，不分块重唱引子或重复上句。未要求音乐/对白不自动添加；无配乐可用 `non_diegetic_music: N/A`，但没有配乐不等于静音环境声。BPM 仍按本片导演设计使用；设计的数值与实际音频测得的 BPM 分开，不能伪称听过音频或凭空报某秒副歌/鼓点。

## 7. 延长、局部重做与恢复

**只延长**：保存并比较旧块正文和共享前言，新增内容只写到新块；保持旧块所用素材、格式、seed、模型/LoRA、尺寸、采样日程、连续设置和 Run 身份等兼容条件。把总块数增加到新目标；当前上游正常续写使用 Progress 开启且 Regenerate From 为 Auto，实际控件与接口仍需核实。共享前言改一行也会改变旧块的有效提示词，不能说“只追加”却重写它。

**只改后半段**：先保留被接受的 Take，再从它续写/分支。重做第 N 块可能影响 N 之后所有依赖块；末尾合并组可能是原子单元，不是任意帧局部修补。先明确保留区间、受影响后续与授权成本，再执行已有范围内的修改，遵守[镜头依赖](shot-dependencies.md)。不要为了小修删除旧历史或把后续重跑藏在一次“重试”里。

**保留与恢复**：固定 seed 只是条件之一，文本不保证缓存复用。查看原始状态、兼容校验、实际复用/新采样计数与输出；只读或不兼容 Take 保留，不修改标记强行复用。Project 是组织容器，Trial/Run 是独立生成历史，Take 是候选结果，命名 savepoint 是固定引用；savepoint 依赖原 Run 数据，并非独立备份，也不恢复完整工作流。另存 workflow 与实际媒体依赖。

上游 Review/Manager 的“准备”“继续”“再试”选择本身通常不采样，要在真实 Queue 后才执行。不要把选中动作报成任务完成。独立新 trial 不复制旧前缀；从 savepoint 续写才涉及旧 Take 祖先链。

Partner 的 `aid_resume_task` 只按当前工具契约恢复已有任务的查询/下载等流程，不等于 Continuum 的采样状态恢复。遇到超时或结果不确定先查询原 taskId/providerId，不换 idempotencyKey 重提，也不虚构跨任务恢复字段。需要新的生成仍遵守 R1。

## 8. 一个原创示例：同镜跨两块

仅演示基于当前解析器的文字编译：假定已确认 T2VA、Timeline、2 块 × 6 秒、无参考图/音频、无真实切镜。此时数值是示例条件，不是所有项目默认。全片 S01 覆盖 0–12 秒，块内各从 0 秒开始；120 BPM 为导演节奏尺，4/4，每拍 0.5 秒，每块 12 拍，非测得音乐节拍。正式生产还须匹配当前工作流和本片完整设计。

```text
[Chunk 1]
integrated_multimodal_description: [Shot 1] 黄昏修理室，灰衣修理员站在工作台左端，蓝色工具箱打开在面前，右侧一米处台灯亮着。中景平视，从人物左前方看向台面，全段保持这一连续镜头。以120 BPM、4/4、每拍0.5秒的节奏尺松弛表演，共12拍。第1–4拍（0–2秒），左手扶住箱体，右手沿铰链合下箱盖后扣上锁扣，听见闭合声才松开左手。第5–8拍（2–4秒），右手握提手，屈膝移重心到左脚再提起工具箱，箱体离台后垂在右腿外侧；相机由静止缓缓向画面右侧平移，维持人物和台灯都在画内。第9–12拍（4–6秒），台灯闪动两下，修理员视线先转向台灯，再带肩膀转向画面右侧，左脚承重，右脚向右前方迈出。末态是右脚尚未落地、右手仍提箱，摄影机已稳定向右平移，光线与机位侧别不变。
overall_soundscape: 锁扣声、衣料声和工具箱轻微碰响，台灯闪动时短促电流声；无人说话。
non_diegetic_music: N/A

[Chunk 2]
integrated_multimodal_description: [Shot 1] 承接第1块：同一灰衣修理员右手提蓝色工具箱，右脚正在向画面右前方迈出，相机在左前方中景并向右平移，台灯仍在工作台右端闪动。沿用120 BPM、4/4、每拍0.5秒，共12拍的松弛节奏尺。第1–4拍（0–2秒），右脚沿上一段路径落地并接住重心，左脚跟上，在台灯前减速站稳，右手箱体惯性前摆后自然回落；相机随减速停住，保留灯座与左手空间。第5–8拍（2–4秒），目光从灯罩落到灯座开关，左手抬起伸向开关，右手继续提箱不换手，触到开关后按下。第9–12拍（4–6秒），灯熄灭，电流声随之停止；修理员看着灯确认熄灭，左手离开开关，身体松下半口气。相机保持原位，不跳轴、不重复上一段合箱或起步动作；窗外余光保持人物和台面的可见细节。
overall_soundscape: 延续修理室底噪、脚步和箱内工具轻响，按下开关时一声清脆咔哒，随后电流声停止；无人说话。
non_diegetic_music: N/A
```

交付前检查：块覆盖/路由、局部时间与真实切点、参考映射、逐字对白、边界动作和相机继承是否成立。生成后针对已知接缝看动作相位、身份/道具/光线，听断词/重复与音轨切换，并核对实际时长及复用报告；不扩大成默认全片审美评分或自动付费重生。后期与最终登记沿用[本地交付](local-media-postproduction.md)和[制作放行](production-acceptance-and-revision.md)。本次知识融合没有进行 GPU 长视频、口型、漂移或性能验收，不承诺无缝。
