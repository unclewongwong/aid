# H3 多模态参考：先确定素材职责，再编译提示词

用于图片、视频或音频参与 H3 参考生成、编辑或续写时。Codex、Claude Code、WorkBuddy 用当前宿主已选的模型完成理解、导演和写稿；完整版与 Mini 共用这套规则。它是一种编写方法，不要求另行调用 Qwen 重写器、部署 vLLM 或增加 LLM 接口。模型名称不能代替质量对照。

已经锁定的逐字提示词、同稿实验不自动重写；已确认稿只修改本次要求涉及的部分。普通文生视频或首尾帧任务沿用[H3 编译](prompt-case-transfer-and-h3-compilation.md)，不为了套格式虚构参考素材。

## 1. 从真实输入建立最小映射

先沿现有工具确认当前路线、生成模式和实际请求预览，再查看本次可访问的素材。每份相关素材记录四件事即可：**实际输入键/顺序与素材 ID → 已观察到的内容 → 本次贡献 → 保留与变化范围**。复用现有项目说明和参考记录，不要求用户另填表。

- 参考图、视频抽帧和原始音频是不同证据。只看视频抽帧不能声称听过声音或验证了完整动作；音频只有文件名或标签时，不推测台词、音色、节拍。需要时使用宿主确有的查看、播放或转录能力；无法读取的关键属性按用户已给信息处理并标明依据。
- 一张图可定义两个人或一个人与一件道具；同一个人也可由数张图共同补足。主体编号不等于文件编号，角色参考不自动变成剧情开场。
- 素材在项目里、Agent 看过素材、生成模型实际收到素材，三者分别核实。文字里的图号不能代替上传或绑定；工作流名称带 Ref2VA 也不证明支持所有媒介。

采用完整参考写法时，标签的职责如下；实际 API 采用 `Image N` 等约定时按预览适配，不能把两套编号混用：

| 标签 | 指向的内容与使用条件 |
| --- | --- |
| `<Subject N>` | 可重复识别的人、物、环境或从素材提取的属性；说明来自哪份真实输入、具体保留什么 |
| `<Picture N>` | 用来规划构图、画面状态或帧锚点的图片；普通参考只提供目标，不声称已锁定真实首帧、末帧或时刻 |
| `<Video N>` | 原视频整体的编辑、续写或时间结构；只借其中人物或动作时，描述该主体/动作的参考用途即可 |
| `<Audio N>` | 实际提交的声音素材；区分复用原声音片段与参考音色、节奏、氛围 |

只定义实际用到的标签，各类别独立编号且前后一致；写清与输入文件的关系，不能按主体数猜图片数量。视频带音轨不等于本次已启用音频参考；需要声音时还须核对真实声音输入或处理路线。

## 2. 保留的是哪些属性

先回答“这份素材对本次结果起什么作用”，再决定保留程度。不要把每个参考都写成全盘照搬：

- **身份或物件参考**：保留能辨认的脸、形体、指定服装/材质；新动作、场景和机位按本片设计。人物换姿势不等于身份未保留，旧服装也不自动成为永久身份。
- **构图或状态参考**：保留本次要读清的站位、持物、接触或终态；说明如何连续到达。首尾帧、普通参考和仅文字目标按真实能力区分。
- **运动或风格参考**：提取相机路径、动作关系或视觉质感，主体、地点和剧情重新创作；不能因用了视频就写成“编辑原片”或“接在原片之后”。
- **音频参考**：只借音色时不带入原台词；只借节奏时不声称复制整条音轨。原声整段保留、局部片段复用和重新生成类似声音是不同要求，须由实际音频输入/后期能力支持。写上“复制”不保证原音不变、逐字一致或精确口型。

需要 `retention_analysis` 时，可用上游的保留级别作简写：可见内容为 `fully_preserved`、`partially_preserved`、`attribute_transfer`、`weak_reference`；声音为 `fully_copy`、`partially_copy`、`reference`、`weak_reference`。每项同时写出具体属性、出现范围和允许变化，不能只给一个等级。`fully_copy` 仅表达要求原声完整保留为最终整个声轨的目标；取片段或叠加其他声音应按实际关系写局部复用，交付仍需真实核验。

任务目的也按关系判断：生成新场景、补足指定帧之间的过程、编辑既有视频、续写既有视频、原声复用或声音参考。可组合本片真正需要的用途，不由文件扩展名机械决定。

## 3. 用当前路线支持的格式写完整正文

完整参考 Ref2VA 路线适用下列六节时，依此组织；普通 H3 三段稿、Pika 已验证的[分层写法](pika-h3-flex-structured-prompt.md)及 Continuum 的路由规则分别保留。六节不能仅凭模型名或上游重写器名字推广到所有工作流。

| 文本段 | 本片应写的内容 |
| --- | --- |
| `subject_definitions` | 主体与真实素材的对应、身份/属性职责；只列必要定义 |
| `summary` | 本次生成或修改的目的，以及素材之间的关系 |
| `retention_analysis` | 各参考保留什么、改变什么、何时出现 |
| `detailed_description` | 实际播放顺序中的画面、连续行动、摄影、表演、逐字对白和同步声音事件 |
| `overall_soundscape` | 环境与物理声源的整体安排；不重复对白正文 |
| `non_diegetic_music` | 本片要求的画外配乐；没有配乐要求不因模板自行添加，明确无配乐时写 `None` |

这些是**同一个 prompt 内的文本标题**，不是新增 Partner API 参数。路线使用 `integrated_multimodal_description` 时，把必要参考关系写进该路线的实际正文，不能同时输出两套重复的动作时间线或要求服务器自动识别新字段。

- 继承既有导演与表演方案，用形容词保留氛围、质感和意图，用具体动作、空间关系和起止状态落实关键过程；参数按需。完整表达受真实输入长度限制，不设统一 350–500 词或固定镜头数。
- `[Shot 1]` 是开场；后续真正切镜才写 `[Shot N] At MM:SS.mmm, ...`。同一镜头的几个动作阶段仍在同一个 Shot 内展开，不为套格式切断长镜；时间码表达导演意图，不保证帧级执行。
- 正文第一次出现主体及用到其参考属性时建立清楚关联，后续持续保持对应；不在每句重复整份外观定义。场景、道具状态和身体/摄影机运动接着前一状态发展。
- 按所选写作指南可用英文描述画面、运镜和声音，用户指定语言或锁定原稿优先；对白、歌词、画面文字保留原语言和原字句。说话人 `(S1)` 等按目标片首次发声次序确定并保持稳定，不等于 `<Subject 1>` 或 `<Audio 1>`。逐字对白只放进该说话人的 `<d>[Language]…</d>`，动作语气写在标签外，详见[对白指南](dialogue-and-generation-quality-gates.md)。
- 原录音中的人声若只作为背景录音播放，不自动变成画内人物发言；音色参考也不授权新增对白。未知原词不补写成“听到的原文”。

### 原创映射示意（假设素材，未生成验证）

假设实际上传的第一张图里有穿灰外套的甲和穿绿围裙的乙，本片只借两人身份，改在车站见面，乙先说“你终于来了。”：可把甲、乙分别定义为 Subject 1、Subject 2，二者都来源于同一张实际图片。保留身份与本片指定服装，车站及新动作是允许变化；不把原图背景或构图锁成车站首帧。乙在目标片最先发声，因此正文为 Subject 2 对应 `(S1)`，台词为 `<d>[Chinese]你终于来了。</d>`。无需虚构第二张图片、额外音频参考或新增切镜。输出给采用 `Image 1` 的路线时，仍明确两人均来自该真实输入。

## 4. 提交前只检查本次相关项

把最终 prompt 与实际请求并排核对：每个标签是否有真实来源、来源是否被送入正确槽位、保留范围是否与新剧情矛盾、对白与说话人是否准确、长镜/切点与声音要求是否仍符合原约定。只修本次需要改变的部分；已经满足要求的稿不再为“优化”反复重写。素材数量、时长、音频和关键帧能力以当前工作流为准，上游重写器的输入容量不扩大视频模型容量。
