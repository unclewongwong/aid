# 整片视觉简报与分镜板协同

适用于广告、产品感官片、生活方式与品牌形象短片，或用户明确提出“同一提示词先生成分镜拼图，再把图和提示词交给视频模型”的测试。目标是让一份简报贯穿两阶段：文字确定整片要表达什么、各场景怎样推进；分镜板把共同外观、光色、空间和景别具体化；视频承担动作、摄影运动、剪辑与声音。它是可选创作路径，不是所有影片必须增加的生图步骤。

## 1. 先写共同视觉依据，再安排场景用途

从用户已有完整稿提取即可，不重复改写或让用户填表。新写简报时，用自然语言覆盖下列对本片有用的信息：

| 层次 | 要写清的决定 |
| --- | --- |
| 整片目标 | 片型、观众应获得的感受或产品认识、交付画幅与时长；品牌和真实卖点来自已确认资料 |
| 共同视觉依据 | 人物/产品身份、服装与包装、环境、有限色板、主光方向和时段、摄影质感；哪些保持，哪些有意变化 |
| 场景用途 | 每段让观众新看到什么：空间、使用体验、材质证据、人物反应或品牌收口；按本片需要组合，不套固定五场景 |
| 可见证据 | 与主张对应的材质和光学事件，例如冷凝水、透光、织物受力、表面反射；质量形容词有具体画面支撑 |
| 动态与顺序 | 每段主动作、观看尺度、必要运镜及落点、前后衔接、不可颠倒的次序和结尾位置 |
| 连续性与声音 | 人物和道具的状态变化、已锁台词/声源、必须保持的内容；缺少声音要求时沿项目约定，不凭片型添配音或配乐 |

共同设定写一次，场景段落主要写变化。分镜板负责外观和构图，文字保留行动意图与必要状态；不能把“图里有瓶子”当作“视频知道瓶盖何时打开”。画幅、清晰度和时长仍要进入实际支持的请求参数，简报中的“4K”不是输出规格。

## 2. 按控制难度决定细节密度

广告中的空间建立、材质观察、简单展示和轻微移动，可以用明确的场景用途、主动作、景别与摄影落点表达，给自然运动留下空间。只有当某个动作阶段、情绪反应或物体状态决定观众能否理解时，才把相应过程展开到可执行程度；不要为达到千字或逐秒填满而增加无关眉眼、呼吸、手指动作。

复杂接触、拆装/开合、液体流向、道具交接、精准体育动作、对白前中后反应，仍按[动作七槽](action-seven-slot-precision.md)、[完整模型稿](ai-shot-design-and-prompt-engineering.md#6-完整模型稿与覆盖核对)和[观看尺度](camera-movement-story-decisions.md#观看任务与可读尺度)补足关键变化。七槽用于检查真实歧义，不要求把每个槽名、数值或每一秒原样输出。画面里没有的人物、表情或声音不为填表新增。

完整指的是本次目标、关键动作、状态与交接没有遗漏，不是统一的字数或写法。视觉简报和详细执行稿可在同一片中配合；简洁不等于只写“高级、自然、电影感”，细致也不等于让所有镜头承担微表情。

## 3. 生图阶段：让整片意图成为可检查的板

- **同稿方法测试**：用户锁定原文时，图片和视频保留同一原文。原文没有写拼图格式，也不能偷偷加排版指令后声称“原稿自动生成整板”；如图片只得到海报或单画面，如实记录这个结果，再按既有授权决定是否另开修订。
- **普通创作或允许适配**：共同简报保持一致，生图端可补“一张多画面分镜板”、阅读顺序、各画面的静态落点及目标布局。不把数秒过程画成同格多重肢体。格数来自观看需要，一个场景可能分成多个画面，不固定六格、九格或一Scene一格。
- 看实际整板：场景是否覆盖、身份/服装/产品形状是否相容、动作起态与持物是否合理。编号、页眉等制作标记放图外映射记录；确需画内品牌文字时区分已确认文案和模型自行添加的小标志。
- 建立足够简单的映射，例如“顶行空间→开场；中间使用与细节→中段；底行产品→收束”。布局阅读顺序不是时间轴，跨格外观一致也不能证明视频时序一致。

三种板的用途不同：本页是**整片多镜头视觉与场景参考**；[四宫格](four-panel-motion-storyboards.md)通常是同一连续镜头的多个状态；[九宫格视觉母版](nine-panel-editorial-storyboard.md)也可用于挑选候选构图。依据用途决定整板引用、选格或裁切，不能看到拼图就自动切成四张，或一律把每格变成一次生成任务。

## 4. 视频阶段：保留共同简报，核实真正的输入职责

先核对当前模型/模式是否支持普通图像参考、整板输入、目标时长与画幅。整板参考宜走已支持的普通参考职责；把它作为首帧会约束开场画面，本片并不打算展示拼图时不能默认这样做。只有首帧输入的路线，不冒充具备整板参考能力：按用户已授权范围选择单格首帧方案或说明缺口。不要因知识指南存在就自动创建新工作流、安装节点或改默认模型。

记录实际素材ID→输入键→职责；ComfyUI检查映射/实际图，API检查当前适配器预览。原图在聊天里可见、项目里列了reference、prompt写了Picture，都不等于已传入模型；也不虚构不存在的素材标签。

**同稿测试与生产适配分开记录：**

- 同稿测试逐字核对图片与视频实际提交的原文，模型参数另行配置；记录有没有额外包裹文本、参考标签、裁切或模型专用结构。锁定原文且路线不接受该写法时先说明冲突，不能暗改后称为同稿。技术接通只说明请求可执行。
- 普通制作保留同一份共同简报，按所选模型的真实结构补镜头顺序、时间安排、动态和引用。这是“共享简报、分别适配”，不再叫逐字相同。H3适配沿用[编译指南](prompt-case-transfer-and-h3-compilation.md)，无需把同稿实验的英文、型号或自由文本格式变成默认。

整板不是可靠的自动剪辑表。单段容纳不下必要动作与阅读时间，或要求精确切点时，沿[成段生成](storyboard-segment-generation.md)分配到可控的段落；不为复制案例把所有影片强塞进一次请求。多段仍需实际状态接力，不能拿整板参考测试当作长视频续写能力证明。

## 5. 从本次错误补有用的约束

在有需要的位置补最小、正向的过程，不把本次错误扩成所有影片的长禁令：

| 问题 | 输入应补什么 | 输出看什么 |
| --- | --- | --- |
| 产品收口后又回到中段 | 场景顺序及最后一次收束的位置；本片若要求单向推进，结束后只保留允许的结尾动作 | 中段是否误出结尾、无功能回跳或重复；不能凭列了Scene就判定已执行 |
| 带盖饮用、开合状态跳变 | 饮用开始时瓶口已打开、盖子在哪里；如开盖本身重要，写出可见开盖→移开盖→接触瓶口；换展示样品时交代新物件 | 嘴/手与真正接触点、盖子归属、状态是否连续；不只看脸部自然 |
| 标签、产品形状或文字变化 | 已确认外形/标识参考与可读尺度；准确文字按任务要求安排可控图形层 | 关键文字的实际拼写、稳定性与阅读窗口；不能因一帧正确推定全片正确 |
| 运动像姿势展示 | 必要的准备、接触、受力/落空与结果，给观众可读机位 | 动作因果及接触前后；抽帧不能替代精确轨迹或口型检查 |

只做本次要求的[放行检查](production-acceptance-and-revision.md)：技术规格与可解码必查；方法测试再检查整板是否变成满屏镜头、场景顺序和目标连续性。记录实际看过的区间与未验证项；失败保留原片，不自动加剪辑/配音/修字掩盖问题，不无限重生。若任务允许后期处理，单独记录处理前后的结果。

## 6. 原创示意：共同简报怎样贯穿两阶段

以下是可调整的结构示意，不是已经生成验证的配方，也不附带新生成授权：

> 为一只无字奶白陶杯做约20秒横幅生活方式样片，表现工作开始前的一段安静停顿。成年人穿深绿针织衫坐在木桌边，同一杯型、服装和窗边环境贯穿全片。奶白、木色、深绿为共同色板，侧窗柔光照出陶釉细微反射、茶水透光和薄蒸汽。先用中景交代人、空杯和茶壶；随后近景看壶嘴向杯内注茶，水流停下、茶面涟漪逐渐收拢；再回到能看清嘴与杯沿的侧面近景，人物握杯柄把杯沿送到嘴边，饮一小口后放回同一桌面，水位略低；最后产品近景停留在杯与散开的蒸汽。注茶段相机轻推至杯内，人物段沿杯的抬起转向脸，杯沿接触时保持可读；最后镜头轻移后落在杯身反光。顺序沿这次使用过程推进，片尾不返回空杯或重新注茶。只有房间底声、注水声和杯底轻触桌面的声音，无对白、配乐和画内文字。

允许适配时，生图请求可在共同简报后补：“用一张多画面板呈现上述观看位置，各画面只选一个清楚瞬间，按使用过程阅读；不加编号或页眉。” 视频请求绑定已检查的板，保留共同简报，按实际模型补必要结构和时间容量。杯中水位、壶嘴/杯沿接触与摄影落点继续用文字说明，不交给拼图替作者决定。若用户要严格同稿实验，两端则使用事先锁定的同一文本并记录实际结果。

## 7. 本机实测所支持的结论

来源：用户2026-10-27提供运动饮料广告完整英文提示词，确认“多镜头整板→整板加同一提示词”方法，授权一次测试，并在看结果后明确要求吸收“整片视觉简报与分镜板的配合”。本指南原创提炼，不收录第三方全文、品牌素材或私人工作流ID。

实际一次GPT-Image-2生图请求未加排版指令，得到2160×3840六画面板；同一原文与整板经本机已核验的H3 V4 Ref2VA路线生成576×1024、24fps、855帧/35.625秒视频。抽样观察到全屏多镜头、人物服装与蓝白视觉基本统一，也看到收口画面重复、约16秒带盖饮用及末尾瓶口结构异常。主品牌/口号在检查帧可读，不代表全片文字稳定通过；未做完整听检或逐帧体育动作验收。

这支持将该方法作为视觉样片选项，不证明原例已被同模型复现、优于详细写法、所有整板可理解或35秒是通用时长。原例模型未确认；没有同条件基线。上述顺序/状态修正是针对实测问题的写作建议，修订后的效果尚未再生成验证；本次Skill更新不重做旧项目或新增付费任务。
