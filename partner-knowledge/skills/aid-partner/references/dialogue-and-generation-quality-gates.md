# 对白、声音路线与生成检查

用于原生音轨、逐字对白、无对白或人物/道具强一致性任务。先按[源头编写规则](reference-and-prompt-preflight.md)解决输入矛盾；检查范围与交付状态统一服从[制作放行与修订](production-acceptance-and-revision.md)。本指南不是额外质检授权，不自动增加测试片、付费转写或重生任务。

## 1. 声音意图、制作路线和验证结果分开

提示词、`shots[].dialogue` 与 `<d>` 标签表达创作要求，不保证输出。原生模型可能错读、漏读、换语言、串说话人或产生额外人声；这些风险不等于所有原生音轨必须弃用。

| 当前需求 | 制作路线 |
| --- | --- |
| 可见人物说锁定台词 | 优先所选模型的原生同期对白，或经核实能由锁定录音驱动画面/口型的路线；不默认“先生成视频，再独立TTS贴回” |
| 用户明确要求配音或提供录音 | 确认素材用途；人物对白仍须处理口型与表演同步，旁白按[音画配对](narration-picture-pairing.md)安排 |
| 允许非逐字即兴表演 | 仅在用户明确允许的范围变化，记录为非逐字，不反向修改锁定文本 |
| 无对白，但有环境/动作/动物声 | 写清允许声源；可保留符合需求的原生音轨，不因无对白而默认静音或重建全部声音 |
| 完全静音 | 使用已核实的关闭音频能力，或后期明确移除音轨；不把“无对白”误解为全静音 |

独立TTS文字正确不证明口型正确。不能自行把正面说话换成侧背面、遮嘴或画外音来规避能力不足；原生对白、真实音频驱动均不可用时说明限制和可选方案，不默改路线。环境声、呼吸、笑声、喊声与对白分别列明，允许一种不代表允许其他人声。

## 2. 最小对白记录

在项目 `story` 保存按镜号关联的对白表，`shots[].dialogue` 保留同一份逐字原文。短片可用少量行，不重复整份剧本。

| 字段 | 内容 |
| --- | --- |
| lineId / 镜号 / 区间 | 唯一编号、全片与段内起止、生成段落 |
| 说话人 | 稳定角色及 `(S1)`、`(S2)` 映射 |
| 锁定文本 | 语言、原文、数字读法、必要停顿 |
| 声音与表演 | 原生/音频驱动/授权配音/旁白；音色、情绪、距离、画内外关系 |
| 时长依据 | 原生表演为读速估计；已有录音写实测时长与素材ID，不混称 |
| 输出与检查 | 实际素材、检查覆盖范围、通过/失败/未验证及证据 |

只记录本片实际用到的音色参数；不为原生对白虚构 `voice` 字段。无对白区间记录允许与禁止的声源。若已选真实音频驱动，先得到所需录音及其时长再提交依赖任务；原生对白不以前置独立录音为条件。

## 3. 按当前能力导演对白

- 为锁定台词分配可说完的区间、呼吸和反应余量。容量不足时，在授权内精简伴随动作、重排时间或拆段；不擅改台词、整片时长或用极速朗读凑容器。
- “音色/风格参考”“复现录音内容与时间”“驱动嘴型和表演”是不同能力。`reference_audio` 的名字不能证明后两者；核对真实输入与说明，不以预览接受字段当作成功实测。
- 只有图片与prompt输入的原生音频模型仍可尝试同期对白，但不能承诺锁定录音级逐字/逐帧同步。只读能力检查不额外耗费生成；需要代表段时使用计划内片段，额外测试须有授权。
- 多人轮流、长句、快速接话增加错读和串角色风险。优先让每段承担清楚的说话人顺序与可读反应；能拆镜才拆镜，锁定一镜到底时不能暗切。
- 只有实际采用独立旁白/配音时，才防止视频再次朗读同一声音；不能为了避免双声，从原生同期对白prompt删除锁定台词。
- `aid_compose` 顺序拼接不代表可任意铺轨、混音或口型修复。后期处理使用已验证且在授权范围内的能力；未经核实不得新增工具参数。

## 4. H3 原生对白与无对白写法

- 全段使用稳定的说话人标识，开头明确身份映射。
- 逐字台词只出现一次：`(S1) ... <d>[Chinese]逐字锁定台词。</d>`；英文使用 `[English]`。标签外写动作、语气、距离和表演，不复述原文。
- `overall_soundscape` 写环境与动作声，不重复台词；未经剧情允许不加入“低语、呢喃、神秘人声”。
- 无对白段用正向事实限定，例如“角色闭口观察，仅听见水流与石块接触声”；有合理呼吸、喊声时另行说明，不能全片一律闭口。
- 禁令不是静音开关。若发现额外人声，只处理受影响区间；移除整条原声会同时失去同期环境与动作声，须先说明后果并按本片授权处理。

## 5. 内容检查启用时怎样判断

本节只规定检查方法，不把技术放行任务升级为全量听检。用户要求逐字核验或报告错词时，检查对应对白及其前后衔接：

1. 逐字比较原文与实际声音；可忽略普通标点/大小写，不以近义替代通过。转写只作定位，识别差异须结合声音判断。
2. 核对说话人、顺序、额外语句与允许的非语言声；口型要求看实际同步，不能仅靠转写。
3. 检查台词完整、切点不截句、反应时间足够；最终混音没有双声、残留旧音轨或音乐盖词。
4. 实际听检使用宿主支持的声音理解或有记录的用户听检。只有播放控件、波形、字幕、空转写或静音检测，不能声称已听过或没有怪声。
5. 能力缺失记录未验证。技术放行可交付并注明内容未审；本次明确要求内容验收却未完成时，交付待审预览，不声称该验收通过。

录音、TTS和音频驱动同样存在漏读、截句或失真风险，不因来源受控就免除已要求的检查。已发现的错误记录文件版本、时间和原因，不自动以换seed反复重生；修订范围、重试授权与重新检查沿用主 Skill。

## 6. 人物、道具与规格连续

提交前按当前镜头维护可见阵容：人数、位置、身份锚点、身体结构、服装与道具归属。只写“保持一致”不够；但不强制为单主体镜头增加复杂表格。

- 查看实际首帧及参考职责。单首帧不能锁定未显示的人物，门后/遮挡后的重要身份须有实际可输入的锚点或获准的覆盖镜头，不能仅列角色卡便宣称锁定。
- 道具记录开始、交接、结束的主人与具体手/位置；无交接动作不应跨角色跳转。
- 内容检查启用时优先看人物首次显露、遮挡揭开、道具变化和接缝；发现错误不靠超分/调色掩盖。未做检查就如实记录，不默认逐帧审全片。
- 技术记录绑定当前项目、镜号、taskId、输出ID、真实宽高和时长；不把后台其他项目状态混入本片，画幅文本不能代替实测。
- 用户要求结尾留白时，在前期明确结果、构图、持续动态、声场与时长；不每段都拖尾，不以冻结/循环假称新的连续表演。

阶段放行、局部失败和版本失效只按[制作放行与修订](production-acceptance-and-revision.md)维护一份记录，不叠加第二套门禁。
