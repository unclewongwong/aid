# 精确对白与生成验收门禁

用于任何包含逐字对白、要求绝对无对白、多人同场、强角色一致性，或准备合成长片的图片/视频生成任务。目标不是在成片后补洞，而是在生成前选对路线、生成后进入母版前拦住错误。

## 1. 先区分“创作意图”和“可验收资产”

项目 `shots[].dialogue`、视频提示词、`<d>` 标签和“无对白”描述都属于创作意图，不是输出保证。带原生音频的视频模型可能改写、漏读、错读、换语言、合并说话人、制造无法辨认的词，或者在无对白镜头里生成哼声、呻吟和类似语言的人声。

因此采用两条硬规则：

1. **必须逐字正确的台词是独立声音资产。** 优先使用用户提供的录音，或项目明确选定音色后由语音路线先生成并确认；保存素材 ID 和实测时长，再据此设计镜头、表演和剪辑。模型原生对白只有通过逐句验收后，才可替代这条受控路线。
2. **必须无对白的镜头不信任原生音轨。** 工作流若有经过核实的静音/关闭音频输入，在请求阶段关闭；若没有，视频原生音频从一开始就只视为草稿，不进入母版，环境声和动作声使用已确认无声或无语言的独立素材构建。不能从另一个写着“无对白”的生成片段直接复制音轨，除非它已经实际听检或转写并证明没有人声。

这不是事后补救，而是制作路线：先决定最终声音从哪里来，再生成画面。技术上能解码、带有 AAC 音轨或提示词写了正确文字，都不算对白通过。

## 2. 生成前建立对白总表

在项目 `story` 保存对白总表；`shots[].dialogue` 仍保留逐字文本。每一行至少包含：

| 字段 | 内容 |
| --- | --- |
| lineId | 全片唯一编号，例如 D07-01 |
| 时间与镜头 | 全片目标区间、镜号和生成段落 |
| 说话人 | 稳定角色名及提示词中的 `(S1)`、`(S2)` 映射 |
| 锁定文本 | 原语言、逐字文本、数字读法和必要停顿；不写同义改写 |
| 音色与表演 | 项目选定 voice/reference_id、情绪、音量、距离和是否画外 |
| 声音路线 | 用户录音、独立语音生成、支持音频驱动的工作流，或待验收的模型原生音轨 |
| 实测时长 | 已确认声音素材的实际起止与持续时间 |
| 画面策略 | 正面口型、侧背面、遮挡、画外声、反应镜头或插入镜头 |
| 验收结果 | 转写、人工听检、说话人/顺序、额外人声和最终素材 ID |

同时列出全部“无对白”区间，写清允许的非语言声源和禁止出现的类人声。若台词仍未确定音色或没有可用的精确声音路线，项目状态只能写“待声音锁定”，不能直接进入最终视频生成与合成。

## 3. 按实际能力选择声音路线

### 必须逐字正确

- 先生成或导入精确语音，听检通过后记录实测时长；镜长按真实语速、反应和出入点分配，不先把长句硬塞进固定视频容器。
- 若要求可见嘴型同步，只使用当前工作流明确公开并经预览核实的 reference audio、audio-driven 或 lip-sync 输入；检查声音素材与角色的映射。模型名称相同不代表当前 Partner 工作流支持音频驱动。
- 当前工作流若只有 `prompt`、首帧/参考图、尺寸、时长和 seed，没有音频输入，就不能承诺“精确对白 + 正面口型同步”。应在创作阶段改用画外声、侧背面、嘴部被构图或动作遮挡、听者反应、道具/环境插镜等拍法，再叠入受控语音；或者经用户同意换到真实支持音频驱动的路线。
- 多人轮流说话、长句、快速接话和同段多次切换会显著增加错读与串角色风险。每个生成段优先只承担一个说话人、一个短句和一个清楚的反应；对白密集场拆成独立镜头或先完成整段受控声音再按声音设计画面。不能为了塞满十秒或十五秒容器，把三四句多人对白压在一次原生音频生成中。

### 可以接受生成式表演

只有用户明确接受近义表达、咕哝、呼喊、笑声等生成变化时，才把原生人声作为创作结果。仍需注明“非逐字”，防止后续误当锁定台词。

### 必须无对白

- 提示词正向写清画面中每个角色的口部状态和可听声源，例如“所有角色闭口，仅有水流、布料与石块碰撞声”；不要只堆“不要说话”等禁令。
- 可写“无其他类人声、无可辨识词语”，但这只是辅助约束，不是静音开关。
- 工作流不能关闭音频时，在生成计划中把原生音轨标为“弃用”，而不是等成片出错后才寻找替换声。

## 4. H3 原生对白的最佳努力写法

只有选择“原生对白候选”时使用本节；它不能代替上面的声音路线和验收。

- 同一角色在全段使用稳定说话人标识 `(S1)`、`(S2)`，并在开头明确身份映射。
- 逐字台词只出现一次，写成 `(S1) ... <d>[English]Exact locked words.</d>`；中文用 `[Chinese]`。`<d>` 外只写说话者、动作、语气、距离与表演，不复述或改写台词。
- 项目 `dialogue` 字段保存同一份锁定文本；不使用斜杠把多个人的多句台词塞成一个无法映射的字符串。
- `overall_soundscape` 只写环境和动作声音，不再次写对白，也不加入含糊的“低语、呢喃、神秘人声”，除非这些就是用户允许的内容。
- 为台词留下真实可说完的区间和反应余量。文字过长时先拆镜或缩短用户允许修改的台词，不能指望模型自动加速且仍逐字正确。

## 5. 进入母版前的语义音频门禁

每个生成段完成后，先抽取或直接监听其音轨，再决定能否进入 `aid_compose`。检查表：

1. **逐字性**：转写与对白总表逐词比较；比较时可忽略大小写和普通标点，但不得以“意思差不多”通过。漏词、添词、错词、乱码、换语言均失败。
2. **说话人**：人数、身份、顺序、音色和台词归属正确；没有串角色、重复句或额外声源。
3. **时间**：台词能完整说完，起止不被切断，不挤占关键反应或下一镜。
4. **静默区间**：无对白镜头没有可辨识词语、哼声、呻吟、伪语言或其他意外类人声。
5. **人工确认**：自动转写可用于定位，但低置信度、非语言怪声和角色音色仍须实际听检。没有转写能力时，不能默认通过，改为人工逐段听检。

将结果写回对白总表。失败段不得进入母版：在用户已授权范围内，只修改该段的声音路线、镜头设计或生成任务；新增付费重生仍遵守主 Skill 的授权和幂等规则，不自动循环重跑。`ffprobe`、完整解码、采样率和声道检查只属于技术门禁，不能代替语义门禁。

## 6. 角色、道具和闯入人物的源头门禁

为每个镜头保存一张“可见阵容单”：允许出现的人物、准确数量、各自位置、身份锚点、服装/尾部等非人形结构、手中道具、道具唯一归属，以及明确禁止的闯入者和重复人物。只有“保持角色一致”不够，必须写成可观察事实。

- 说话近景、多人同框和开门/揭示后的首个画面属于高风险画面。先生成并验收实际首帧或动态分镜：逐人对照参考脸、发型、鳍耳/鱼尾、服装和尺度；逐项核对人数及道具归属。错误分镜不进入视频生成。
- 单首帧工作流不能同时精确锁定多个未出现在首帧中的人物。关键多人镜头应使用包含正确阵容与位置的合成首帧/分镜，或拆成分别锁定身份的覆盖镜头；不能只靠提示词列四张角色卡就宣称已锁定。
- 门、遮挡物、暗处、背景群众和画外进入位置要单独检查。模型容易把“打开门/揭示王座”理解成新增人物亮相；提示词须写门后实际主体及准确人数，首帧/中间关键画面也要覆盖门开后的状态。
- 角色持物必须有唯一主人。每段开始、交换和结束都记录道具在哪只手或哪个位置；没有交换动作，就不允许道具跨角色跳转。
- 每个生成段进入母版前，在段首、人物首次完整出现、遮挡揭开、道具变化和段末检查实际画面。发现身份、数量、身体结构或道具错误时拦在该段，不用后续超分、调色或整体剪辑掩盖。

## 7. 画幅、任务归属与结尾门禁

- 为当前项目保存任务台账：镜号、taskId、projectId、工作流、宽高、画幅、参考素材和输出 ID。判断画幅时只核对当前项目任务及实际输出宽高，不把后台其他项目的任务编号混入本片。
- 生成前同时核对请求宽高与工作流输入映射；生成后读取实际视频宽高。`16:9` 文字、分镜构图和任务卡都不能替代 `width:height` 的实测。
- 结尾留白在全片逐秒设计阶段写入：最后的局部结果先成立，再用一个构图稳定、仍有微小生命或环境运动的长镜头承载余味；明确标准速度时长、声场衰减和最终画面状态。不要在每个段落结尾都留白，也不要等总片完成后机械重复最后几帧。

## 8. 全片进入生成与合成的放行单

只有下列项目都可追溯时，才进入批量视频生成或最终合成：

- 全片对白总表完成；逐字对白已有受控声音资产或明确标为待验收候选，所有无对白区间有最终声音路线。
- 每段人物阵容、数量、身体结构、道具归属和实际首帧/分镜已经检查；关键揭示状态有图像锚点。
- 当前项目每个任务的画幅和 ID 可追踪，不与旧项目混淆。
- 每个完成片段同时通过视频语义检查、对白/无对白语义音频检查和技术解码检查；没有把“提示词写对了”当成“输出通过了”。
- 结尾长镜头和声场已在时间线上预留，而不是用后期补长挽救。

保留未通过项和原因。门禁的作用是阻止错误素材进入下一阶段，不是自动评分、自动消费额度或无限重生。
