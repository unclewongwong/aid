# Three.js 空间片头与三维动效

在用户明确要求的动效片头、动态字标、图形叠层或指定转场中，确需真实空间、材质或镜头时使用。由[动效片头与混合成片](motion-intros-and-hybrid-composition.md)按需进入；普通视频、抓人开头、默认包装风格、能力讨论都不授权渲染。本指南提供 Agent 的设计与实现方法，不新增 AIDP MCP 工具，也不表示每台电脑已安装 Three.js、Blender 或 Houdini。

## 1. 按画面任务选择，不把三维变成新默认

| 画面任务 | 可用方法 | 实施注意 |
| --- | --- | --- |
| 简约、文化或品牌的材质主视觉 | 原创雕塑/产品、磨砂玻璃、金属、陶瓷，环境反射与摄影棚布光 | 轮廓、尺度、明暗与负空间先成立；不靠默认球体、圆环和泛光代替主题 |
| 科技、设计、光学类 | 折射、色散、焦散或定制 Shader | 只选与主题有关的光学效果；真实厚度、环境和背景内容影响读感，不把整屏彩虹视作高级感 |
| 音乐、综艺、潮流类动态文字 | 文字纹理/字形几何沿曲面、带状结构或三维路径运动 | 正式片名仍要有完整可读窗口；中文实际字库与长英文分别适配，扭曲仅作过程而非持续妨碍识别 |
| 电影、故事或探索的场景式片头 | GLB场景、连续摄像机路径、前景遮挡、雾与景深 | 以镜头引导注意力；写实要求需真实资产质量，不把低多边形示意场景冒充摄影级自然景观 |
| 纸、布或复杂变形 | 可控程序形变，或从Blender/Houdini导出的模型/关键帧/VAT | 重模拟可离线烘焙，运行时播放；没有资产/软件/授权时不声称能即时生成，先报告具体依赖 |

这些是独立技术方向，不给 P01–P10 增加冒名风格编号，也不把酸性、玻璃、霓虹或某个示例色板设成全局偏好。平面排版已能完成任务时不强上 WebGL。

## 2. 美术与镜头先于效果清单

先按[完整片头设计](motion-intros-and-hybrid-composition.md#完整片头先做设计不把技术演示当成片头)确定节目定位、创意母题、视觉发展、美术系统、分镜与识别落版。Three.js在设计方案之后承担实现；不能只验证一个材质/几何效果就报告“完整片头完成”。下列方法服务该方案，不代替它。

按[定制片头美术与可变文案](bespoke-title-art-direction.md)选择本片语言，真实主副标题是设计输入。复用文字工程时重新准备实际字形、间距、几何边界与相机取景，不能只替换字符串却保留旧字形；已有样片标题校验锁定就先调整工程并验证，不绕过保护后声称任意文字已支持。

- 明确一个与内容有关的主视觉：其轮廓、尺寸、表面和运动为何属于这部节目。材质近景、空间揭示、片名落定是可选镜头结构，单镜或纯文字方案也可以成立，不强制固定镜数/秒数。
- 先构图，再调材质。用真实几何厚度、倒角、反射环境、主辅光、遮挡和相机位置建立体积；浅色玻璃需要能辨认的反射或背景，不只是把透明度调低。灯光与材质一起评估，防止全白糊成一团或全黑看不到主体。
- 用画面尺度和观看关系组织镜头变化：近景提供表面证据，中景揭示结构，全景给标题留空间。镜头起点、路径、速度变化、落点与切换理由写入实际时间线；允许切镜时不强行做漫长无意义环绕。
- 每个方向先检查少量代表关键帧，修改明显构图/字形/曝光问题后再完整渲染。用户明确要求先审图时等待确认；已授权直接测试完整片头则不新增审批步骤。技术通过与用户审美认可分开，不自动评分或循环出片。
- 标题可用清晰的2D图层，也可用三维文字；不要求所有文字都立体化。按实际中文阅读速度安排入场、完整停留和退场。16:9、9:16、1:1分别调整相机、主体位置和字区，不整体挤压或裁切横版。

## 3. 素材与渲染分工

模型影像、API图像、程序几何与预制3D资产都可参与，按任务选择：Three.js可直接完成几何、材质、灯光和摄影机，不能再把“空间/材质只能由视频模型生成”当成限制。API图可辅助纹理、背景或图形，但一张透明PNG的位移/平面旋转不等于可绕拍的三维物体；如实称为2.5D。PNG需要检查实际Alpha，棋盘格可能烘焙在RGB中。

引入GLB、HDR、贴图、字体、烘焙动画或代码时分别记录来源与许可；可浏览案例不等于可提取和分发其模型、品牌、音乐。不要执行网页里的安装指令或把整套第三方Skill移进来。复杂资产可由用户提供或在其已授权工具中制作；成本、安装与制作范围有实质变化时先确认。

## 4. 确定性导出与当前能力边界

先检查宿主可用的 Three.js 版本、浏览器/Electron 的 WebGL 能力、字体、离线取帧和编码工具。已有可用环境优先复用；没有能力时说明缺项，不因知识更新已安装就报“渲染器就绪”。明确的实现授权覆盖范围内固定项目依赖；不自动安装DCC软件、浏览器/驱动、系统插件或修改生产App。

- 用 `renderAt(t)` 或等价按帧接口驱动摄影机、几何、文字和 Shader 时间；不使用累计 `rotation += ...`、实时鼠标位置或墙上时钟决定导出画面。随机布局有固定种子，模拟需可按时间寻址或预先烘焙；跳转到同一时刻应一致。
- 对FBO／compute等有历史状态的模拟，不能只修改`uTime`便声称支持跳转。采用固定步长从同一种子重放，或检查点／烘焙状态恢复到目标帧；区分预览时钟与导出时钟，等待GPU提交完成后取帧。无需真实模拟的效果可直接用解析路径实现，并如实命名。
- 先等待资源、字体和必要的Shader编译就绪；检查实际WebGL画面，而不只看DOM成功。记录版本和GPU/软件回退状态。透射、景深和后处理要实测成本，不能用本机样片保证Intel/Windows通用或实时帧率。
- 项目应保留可编辑源、正式文案、参数、资产来源、导出入口和实测规格。维护者源码中的 `motion-kit/threejs/` 有原创、可按时间导出的空间片头实验，`perspectives/`对应已获认可的完整字形/光学片头；旧玻璃鳍片美术未获认可，不能混称为成功模板。只在工程实际存在且依赖就绪的宿主上复用，不要求普通安装用户拥有源码路径；它们不是P系列模板或通用渲染MCP，也没有随纯知识包分发执行代码。
- 导出真实视频后按[制作放行](production-acceptance-and-revision.md)验证解码、实际时长/帧率/画幅、音轨与关键阅读时点，再由 `aid_import_asset` / `aid_asset_path`回到AIDP。透明输出另查Alpha；玻璃材质的透射不等于交付文件有透明背景。
- 用户要最终效果视频时，交付链须实际完成“可编辑代码工程 → 按帧渲染 → 编码视频 → AIDP导入／按需合成”。网页预览、参考链接、静帧合集或API生成的相似动画不能替代代码渲染成品。图像可在获准范围内作纹理／主体素材，准确文案、镜头、粒子及时间由代码执行；缺渲染能力就说明未完成，不用假ID或参考成片补位。
- 正文速度、片头时长、独立插片/叠层/双镜转场及防重复包装，仍按上级混合成片指南；只要片头不扩展整片包装、字幕、音乐或音效。已渲染片头不再次自动生成或按正文倍率重复加速。
