# 参考图与提示词：生成前消除歧义

用于有固定人物、连续剧情、逐字对白或复杂揭示的分镜图与视频提示词。优先解决输入本身的错误，再提交生成；不能把本可在文字和参考图阶段发现的问题推迟到成片验收。本指南是 Agent 的编写与提交前复核规则，不是客户端自动拦截功能，也不能承诺生成模型零错误。

## 1. 分开身份、状态和运动

- **身份基准**：用户确认的原始人物图决定脸型、五官比例、年龄感、发型、身体结构与服装。后续分镜只定义剧情状态，不自动成为新的身份标准。少数有辨识度的正向特征比“同一个人、绝不换脸”更有用；特征必须来自图像，不凭名字推测。
- **状态图**：每张分镜是某个时刻的静止画面，写清准确人数、可见人物位置/朝向、景别、肢体姿态、道具主人及动作进行到哪里。不要在单格里同时要求“关门→开门→四人进入”三个状态。
- **视频过程**：从实际起始状态出发，写谁因什么触发、怎样运动、沿什么路径、谁随后反应，以及结束时的新状态。画面没有的必要起始条件，先在分镜阶段解决，不让视频模型凭空补齐。

在项目说明保留完整设定；每次请求只带本镜相关的身份锚点、状态与变化。不要给模型塞入全片所有人物、背景故事和互不相关的禁令。

## 2. 写分镜图提示词时先定清楚

按本镜需要组织以下内容，不把它们当新 API 字段：

1. **实际参考映射**：哪一张上传图对应哪个人物，分别保留身份/服装还是只参考环境。用本次请求真实顺序，不沿用上一任务的图号。明确角色卡的金框、底座、标签不是场景内容；角色冠饰、贝壳服装与尾鳍则是身份部分，不能一并去掉。
2. **角色区别**：例如黑长发、金绿色眼睛、雀斑和鳍耳的角色，与暗红尖刺盘发、深色唇色和黑红肩甲的角色分别绑定；不能只写“两个年轻美人鱼”。取景看不见的特征不要求同时可见，脸转到侧面不能仍要求双耳完整对称。
3. **人数与持物**：具体写画内有哪些人，背景/门后还有谁，笔记本由谁哪只手持有、其他人双手在做什么。道具转手必须有剧情动作，不能靠跨格跳变完成。
4. **单格状态与空间**：明确前中后景、人物自身左右与画面左右、视线目标和遮挡。以姿势、尺寸关系和地标描述，不用“气场强大”“形势严峻”代替构图。
5. **风格落点**：继承原图头身比例、面部造型与材质体系；电影感落到主光方向/软硬、明暗关系、景深和观看重点。不要用“真人写实”重塑原本的Q版面孔，也不要给每个物件同等锐度和亮度。
6. **四宫格职责**：每格一个指定时刻，同一身体结构、服装和空间关系。先检查各格，再裁成独立画面按真实输入能力使用；不默认把整板交给一个图片输入就能控制四个时刻。

写完后直接对照实际将上传的图片。图里已有双腿、错误脸、错道具时，先修图或在授权范围内重新准备正确参考，不用视频负面提示抵消错误视觉输入。不能因为一格正确就让其余错误格进入请求。

## 3. 图像是否真正约束到目标

项目 `references` 列出四张人物图，不等于视频请求携带四张图。提交前将“实际 assets 键→素材ID→图像内容→模型职责”逐项对应；只有一个真实首帧输入，就如实按单首帧能力设计。工作流名称含 Ref2VA、PDD 或输入名为 reference_image，都不证明支持多参考、关键帧时序或语音驱动。

闭门背影首帧只能约束可见的背影，不能充分定义门后新出现的脸。遮挡揭示、转身露正脸、首次多人同框等身份关键变化，应在分镜阶段准备正确可见状态，并确认它能通过实际模式输入：

- 模式支持合适的辅助参考/首尾状态时，绑定真实素材及职责，不把普通参考夸称精确时序控制。
- 只支持首帧时，在允许调整构图的范围内，让重要人物在起始画面已有足够可辨识的局部/侧面；或在允许剪辑时，把揭示后的正确画面作为独立镜头首帧。
- 用户锁定“完全遮挡后首次亮相的无剪辑长镜头”而当前模式无法提供身份约束时，明确能力与风险，不暗改叙事、预泄露悬念或假称已锁定。正确图片只存在项目资料中却未传给模型，不算解决。

## 4. 视频提示词要通过六项一致性检查

| 项目 | 生成前必须消除的问题 |
| --- | --- |
| 图文一致 | 开场人数、脸、姿态、道具与实际首帧相符；图中已合上的本子不能无过渡再执行合上；正文不要求不存在的输入图 |
| 身体与世界一致 | 鱼尾角色用摆尾、游近、悬停、上身挺直等动作；不用“迈步、脚步、膝盖、靴子”暗示双腿。接触、重力与声音服从已建立世界，幻想规则可以存在但须一致 |
| 时序一致 | 先看见/听见触发再反应；有可走通的路径和完成时间；每个动作有起点和终点，人物不无因移位 |
| 摄影一致 | “连续无剪辑”不能同时写硬切；真实切镜才新增 Shot；近脸特写不能同时要求全身尾鳍完整可见；固定焦段不能又变焦 |
| 声音一致 | 无对白段不写“嘟囔、试图解释、含糊低语”；静默反应用目光、闭口与手部动作表达。保留剧本允许的呼吸/笑声时明确种类、位置，不泛化成自由人声 |
| 时间容量一致 | 台词、运镜、动作和反应都留得下；不同说话人没有非剧情所需的重叠；不能一面写克制停顿，一面塞入需要极速朗读的长句 |

抽象情绪可以作为方向，但随后必须有可观察的表演。例如“威严瓦解”改写为“他先把零食藏到背后，看向三个孩子，目光落回地面；嘴唇闭合，扶椅的手慢慢松开”。不用堆积眉毛、鼻翼、手指等所有细节，选能说明本次情绪变化的关键动作。

声响有具体声源和发生条件：“笔尖离开纸面，书写声停止”，而不是“笔尖悬停的细响”。环境水声、混响或配乐不能同时要求压住又突出同一句台词。沉默不是“无可辨对白”——后者仍可能留下伪语言；明确本段只有哪些非语言声源，以及人物是否发声。

## 5. 对白先算得下，再交给声音路线

锁定每句原文、唯一说话人、语言、声音路线和起止区间。英文按词数/秒数换算只是拥挤预警，中文不能套英文词速；不能把估算标成实测。选定录音/独立语音路线时以实际声音时长排镜；原生对白路线按表演读速估算、留停顿，并标明仍有生成不确定性。

实例：`You need your tricks just to remember who you are.` 共10个英文词；放入1.7秒约为353词/分钟，和冷静、清楚、有锋芒的表演方向冲突。不要仅补“逐字清晰”四字，应在授权内缩减周边动作、重排节拍或拆段，为该句先预留约4–5秒作设计起点，再按实际声音/表演确定；这不是适用所有台词的固定时长。不改变用户锁定文本来迁就容器，也不擅自延长全片。

H3原生对白的结构规则见[精确对白与生成验收门禁](dialogue-and-generation-quality-gates.md)：稳定的说话人标识、原文只在 `<d>` 中出现一次、动作语气放标签外、声景不复述台词。基础模式和完整参考模式分别使用各自支持的结构，不凭工作流名称套模板。多次转场、四句多人对白和复杂动作挤进十秒，应先改生成分段和导演设计，不能用更长提示词增加负荷。

声音路线也在生成前确定：需要严格逐字时优先受控录音/语音；使用原生对白时承认其限制。没有已核实的音频驱动能力，就不能保证指定录音的正面同步口型。用户已指定原生同期声或可见说话时，说明冲突，不静默换画外音。具体路线和工具能力沿用对白指南。

## 6. 画幅与结尾同样在源头决定

- 原始人物卡可以是竖幅，影片帧仍应按目标横幅重新构图。图片请求参数、四宫格整板/单格比例、视频节点真实宽高分别核对；“16:9电影感”不是接口参数。不要拉伸竖图冒充横幅，也不把其他项目任务当本片证据。
- 用户要求长镜头留白时，先在全片原速时间线给最后结果之后留出有意义的连续区间：谁停下、看向哪里、哪些微小动作继续、镜头何时停稳、声音如何退去。避免最后一句刚结束就到片尾，也不要默认用定格、循环或慢放补长。没有通用的固定留白秒数，按本片情绪设计。

## 7. 提交前的最小复核

只检查本次任务相关项：实际图号和输入职责对得上吗？人物脸和身体、持物正确吗？开场与文字一致吗？揭示目标是否有真实图像约束？动作/摄影/声音是否互相矛盾？每句台词和反应是否装得下？画幅参数和结尾安排是否明确？

发现图文错误先改输入，发现时间冲突先改设计，发现能力缺口先解决路线；不要提交后等待模型替作者做决定。修改共享设定后重查尚未提交的关联任务，不影响独立任务并行。最终内容检查仍是必要兜底，但不能代替上述源头工作。只修改Skill不等于已改写旧项目提示词或已重新生成影片。
