# MG 动态设计：把内容变成有因果的运动

用于用户明确要求的 MG 动画、动态图形解释片、动态文字、品牌动效、片头或图形转场。来源、改写范围和许可证见[来源与许可](mg-styles-notices.md)。本模块是可用于 Codex 创作与代码制作的知识，不是已经安装的 15 套渲染器或 App 新预设。

## 入口与既有流程

- 先识别本次要的是方案、关键画面、独立 MG 成片，还是已有影片的局部包装。只交方案不渲染；用户已明确要成片且条件齐备时正常制作，不增加仪式性审批。
- 普通剧情片、真人摄影、导演风格、“开头抓人”以及讨论参考仓库，不自动触发 MG。给影片加动效仍遵守主 Skill 的 R4/R5；同意一种效果不等于同意全片包装、字幕或声音。
- 独立解释动画接[解释动画指南](explainer-and-art-animation.md)；片头/混合合成接[动效片头指南](motion-intros-and-hybrid-composition.md)及[定制片头设计](bespoke-title-art-direction.md)；实际需要空间关系再读[Three.js 指南](threejs-spatial-motion-design.md)。不替换既有制作、合成、项目登记和交付契约。
- 从[15 种方法卡](mg-style-catalog.md)选择与内容相容的主风格，必要时加一个分工明确的辅助语言，不默认把全部效果混合。方法卡 slug 仅供文档检索，不是 MCP 的 `styleId`、工作流 ID 或 API 参数。
- 保留现有 20 种画风、20 位导演、P01–P10、内置片头及 Variety Kit 的原分类与编号；MG 主要决定图形组织和运动语法，不覆盖叙事、真实人物身份、用户品牌或锁定对白。

## 从主题到制作简报

先写一句“观众最后理解/感到什么”，再找一个能承载变化的视觉母题。把散乱变有序可以让同一组对象聚合、排序、落位；不要用四张互不相关的漂亮海报替代论证。镜头/版面之间交代谁继续运动、哪条线延伸、哪个形状变成下一个元素。

已有片名、标志、文案、时长、画幅和指定工具优先保留；只对确有缺口的关键条件询问。品牌可使用用户有权提供的真实品牌，不强迫改成虚构品牌。数字、单位、图表比例和引述有来源；装饰性界面不伪装成实时监测。

简报按需要填写，简单作品可合成一段，不强制全套表格：

```text
Output / deliverable: [方案、关键画面、独立MG或局部合成；实际尺寸、帧率、时长、透明度要求]
Locked content: [逐字文案、品牌资产、事实与不可改动项]
Creative idea: [一个观众能读懂的变化；视觉母题如何贯穿]
Style grammar: [方法卡slug；形状/材料、字体层级、色彩、布局、运动与转场]
Beat chain: [时间范围；进入状态→动作及意义→退出状态；文字的可读窗口]
Assets / route: [已有素材、需新做素材；矢量/Canvas/3D或用户指定生成路线；实际依赖]
Audio scope: [无声、保留原声、或已授权的音乐/音效；需要时列事件锚点]
Checks: [该片最容易失败的两三项；待用户选择/待核实事项]
```

**原创应用例，不是固定模板：**用户要 8 秒无声的任务整理 MG，锁定文案“灵感，各归其位。”选 flat-vector：0–2 秒三张可辨识的便笺围绕同一个收纳框错位停留；2–5 秒框的三条分隔线依次展开，便笺沿线进入对应格；5–6.5 秒收纳框外轮廓自然缩成用户标志的承托形；6.5–8 秒逐字文案保持稳定。读不完就减少画面中的辅助文字或与用户协商节奏，不偷偷延长锁定时长。没有授权声音，就不为“卡点”补音效。这些秒数只属于此例。

## 不同模型/工具接收不同内容

- **Codex 代码制作：**把简报落实成层级、几何、时间函数、素材依赖和可重复渲染工程；按实际环境选择已有可用工具。优先复用已核验的本地制作流程，不因为上游用了某库就安装整套依赖。
- **GPT/Qwen 等关键画面：**提交该时刻可见的主体、构图、空间/材料、光色、准确文字与保留项。运动时间轴留在制作简报，不把整段 JavaScript、`renderAt(t)` 或 CSS 喂给生图。真实摄影才按既有条件加载摄影质感；矢量、像素、剪纸、手绘不套真人毛孔/镜头柔化段。
- **H3 等生成视频：**把选定风格编译成实际能看见的运动、状态承接及声音范围，按已选工作流的真实输入传递。不要声称关键词可以保证逐字排版、严格曲线或逐帧同步。用户指定模型时不能悄悄替换成代码渲染；若精确图文不适合生成，说明后提出分层制作选项。
- **图片分镜：**保留既有逐镜复杂度判断和 4K 整板规则；四个 MG 设计帧不自动等于四宫格生成任务，更不等于四个新镜头。

## 制作方法：先看得懂，再动得有意义

1. 根据作品复杂度检查少量关键状态：起始、转折、落版，以及最危险的中间形变。先解决信息层级、字形、留白、遮挡与素材比例；不是每片固定四帧或四轮审批。
2. 建立共享事件表：时间、对象、动作、叙事作用、承接对象。运动服务状态变化。弹性适合部分 flat-vector，Bauhaus 可用理性落位，pixel/cel 常需阶梯运动；不要全套使用相同 bounce、粒子、扫描线或颗粒。
3. 若已授权声音，再把音频 cue 绑定视觉事件：撞击瞬态对齐接触，whoosh 的掠过峰值对齐穿越，riser 的终点对齐揭示；不能仅让音频文件起点与动画起点一致。无声作品也可以有清楚节奏。BPM、响度、采样率和声道按交付要求，不继承样例常量。
4. 确定性离线渲染使用帧时间驱动的 `renderAt(t)` 或等价机制。随机数设种子，物理运动预缓存或用可复现状态；乱序跳转到同一时间与顺序播放应一致，不能依赖上一帧累积。像素/手绘是否使用运动模糊按风格选择。
5. 字体、贴图、视频解码等资源就绪后才捕获；中文字体必须检查实际字形覆盖。缺资源、页面错误、透明度/色彩错误应报出，不把空帧当成功。浏览器截图→视频编码只是可选路径；代码文件不是已经生成的视频。
6. 按实际交付规格导出并查看文件。不要把上游的 10 秒、1080p、30 fps、120 BPM、结尾 1 秒停留当全局规则；固定片头不额外套 1.2× 变速。输出用新版本路径，不覆盖用户母版。

## 检查与交付边界

- 技术：实际时长/帧率/尺寸、首尾帧、黑帧/缺字/裁切、透明边缘、最终缩放下的线宽与可读性；需要确定性时验证跳时及重复导出。声音已授权才检验音画锚点、峰值与剪切。
- 表达：转场有对象与语义承接，主体层级稳定，关键文字真的有阅读时间；检查变形中段、镜面/玻璃的可读性及 HUD 的真假信息边界。记录具体时间点和问题，不能只打“9 分”。
- 能修复的确定性制作错误在原授权内针对性修复；新付费素材、改变路线/剧情、增加声音或扩展制作范围需先确认。无进展时说明原因和选项，不自动无限重渲染、不启动评委 Agent 打分循环。
- 交付时区分“方法已接入”“静态草图”“实际渲染样片”“用户验收”；选用某卡不证明该风格或所有 15 种都已跑通。知识更新不安装 Chrome/Blender、字体、采样，也不增加服务工具。
