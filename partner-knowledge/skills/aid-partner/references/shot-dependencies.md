# 镜头素材依赖与局部修改

用于制作中途替换角色、服装、场景、声音、首帧或修改镜头。依赖记录帮助判断影响范围，不触发自动重跑。

## 保存最小可恢复记录

在项目 story 中按镜号记录本次实际使用的设定版本、参考素材 ID、已知 taskId 和输出素材 ID，以及相邻镜头衔接所依赖的状态。只填真实返回的信息；尚未生成的任务标为未生成。继续任务时读取 Partner 当前项目和原任务，不能只凭聊天里的旧表提交。

可用简表：镜号／使用的角色与服装版本／场景与首帧 ID／语音素材 ID（如有）／原任务与输出／衔接状态。简单作品不用补齐无关列。主 Skill 的 shots 字段保持不变，这份说明不是新增 API 参数。

## 判断修改范围

1. 对照旧版确定到底改了什么：身份、某场服装、布景位置、某句旁白、镜长，还是仅修改文字表述。
2. 找出直接引用该版本或素材的镜头，再检查必要的衔接依赖。例如上一镜结束位置改变，下一镜从该末帧起拍时也需检查；只改片尾旁白，不自动影响所有角色镜头。
3. 将涉及项区分为“须改计划”“可能需要重生成”“只需重新剪辑/合成”或“无影响”，写明依据。没有查看成品时，不声称成品存在具体穿帮。
4. 在用户授权范围内更新计划。替换素材使用 aid_update_references 的现有能力，保留原任务、素材和版本。新生成使用新的稳定 idempotencyKey；原任务查询继续使用原 taskId。
5. 用户锁定修改范围时，只执行指定部分；可能影响范围外镜头的连续性应说明，不顺带生成。用户已经授权相关重做时直接执行，不再重复索取同一授权。

“受影响”不等于“必须重做”。例如换一张更清晰但内容相同的角色参考，不自动判定所有旧镜头失效；先根据用户要修正的内容和实际依赖判断。纯剪辑或音量调整能完成的改动，不默认重新生成视频。

## 依赖能力边界

当前由 Agent 在项目文字与真实素材/任务记录之间维护对应关系。不要宣称 Partner 已有自动依赖扫描、失效传播或一键局部重建；完整自动化需要独立的数据结构和工具实现。失败恢复、未知提交和付费重做边界继续按主 Skill 执行。

替换后同步更新 [制作放行与版本记录](production-acceptance-and-revision.md)：旧素材保留但标记已替代，受影响验收标记过期；合成清单绑定当前通过的源文件和入出点，视频/音频分别记录。检查修改区间两侧及回切旧段后首次人物/道具显露，防止修补末端重新接入原错误镜头。

方法来源：借鉴 Higgsfield [Brand Lock 的产物依赖与修订](https://github.com/higgsfield-ai/skills/blob/d071406147a37b835bed09543d85ab3e9bd85c7d/higgsfield-brandkit/references/brand-lock.md)，为电影镜头管理原创改写，不调用其品牌状态脚本。

## 一个镜头内的多张动态分镜图

镜号与关键画面编号分开；在story中关联本镜K01–K04等动态状态、源四宫格、裁图坐标/实际尺寸、素材ID与目标时刻。只改某个关键状态时，先检查相邻图间运动、信息显露和退出状态是否仍能连续成立；不把换一张图当成新增镜头或重新生成整片的授权。更新实际素材继续使用已有引用工具与原镜号，生成段落映射随改动同步。
