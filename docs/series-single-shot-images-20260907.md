# 连续剧逐镜 1K 首帧

状态：源码完成，未发布或更新运行中的 Companion。

用户要求分镜稿确定之后、视频生成之前，一镜单独生成一张图，需要几张生成几张，不用默认 16 张或四宫格填充。

连续剧使用的隔离 Story 执行器现在将新图片任务路由到逐镜生成。任务清单取已通过定稿合同的实际 `storyboards`；原来的四镜分组仅用于识别和恢复旧的付费母图任务，不再为新连续剧提交母图。6 镜就是 6 次单图请求，末批不补齐。所有首帧完成后才进入视频阶段。已有可用图像跳过；单图任务号继续即时持久化并断点查询。旧母图任务沿用原裁切恢复流程。

单图请求增加 `resolutionOverride`，由浏览器请求准备器经过 `/api/generate`、单图编译器传至供应商。当前使用的 GPT Image 2 为 `n:1, resolution:1k`，角色、服装、场景、道具和风格参考仍通过原有单图编译流程传递。GPT/Nano Banana 支持 1K；其他模型保留其原生支持档位，避免发送不支持的参数。普通 Story 的四宫格功能和公共角色/道具资产分辨率不变。

创建普通故事时的默认剧本镜数仍是 16，这次修改的是首帧生产方式与数量来源，不修改分镜创作规则，也不自动重写已批准剧本。未重生成用户已有图片或视频。

前台展示“逐镜 1K 参考 · 张数按定稿镜数”，新能力 `seriesSingleShotImages` 防止新版页面交给旧 Companion 后继续按四宫格生成。发布此功能需要同步 Companion。

验证包含 3/6/10/17 镜无填充、只生成缺图、继续旧母图任务，以及请求准备器→API→真实编译器→模拟供应商的完整参数和参考图传递。没有调用付费生图或视频，也未增加画面质检。

验证结果：图像请求/模型/恢复相关 51 项通过，连续剧相关 157 项通过；TypeScript、生产构建和 git diff --check 通过。新版源码尚未装入本机运行版，未发布网页或安装包。
