# 连续剧台词超时自动压缩

2026-09-07，本地完成，尚未发布。

## 问题

用户制作预检提示镜头2至少19.6秒、镜头5至少17.8秒，超过H3的15秒上限。代码核查发现两个缺口：编剧检查使用字数/空格词数预算，制作检查另算中英混合文本、标点停顿、起声和收尾；已保存且素材指纹未变的剧本只检查串镜台词，未重查时长。因此制作前才可能发现旧稿超时。没有读取本次报错项目的具体台词，不将代码缺口当作该项目唯一原因的实测证明。

## 处理流程

1. 编剧与制作共用`speechRuntimeSeconds`，计入对白、交接、至少0.8秒起声和1秒尾画面。能在15秒内延长原镜头解决的，优先保留全文。
2. 超时则按当前句子占比给出保守字数/词数预算，只允许修改指定台词路径，保留轮次、说话人、动作、场景与镜头数。
3. 候选先通过结构和时长校验，再发起独立文本模型原意复核。核对事实、数字/价格、否定、条件、因果、人物意图、情绪转折、伏笔与回应关系；每句必须明确通过并说明理由。
4. 不合格、复核不可用或格式错误不覆盖原稿，最多3轮候选。候选和复核至多各3次文本模型请求；不重买图片/视频。
5. 旧剧本进入Story前同样检测；成功后保存前后台词记录、同步故事文本/分镜/规划/视频分段对白，仅继续未生成片段。图片、音色和未受影响的付费视频保留；受影响片段已有视频任务/缓存/交付物则拒绝自动覆盖。

当前已完成的逐字原稿模式（authored_screenplay）继续保持逐字合同，不自动压缩，也不暗中增加镜头或修改设定集数。无法保留原意时停在原稿，后续需要另行安排镜头/对白。模型复核降低语义漂移风险，并不构成数学意义的原意保证。

- 新增`tests/series-timing-autorepair.test.mjs`覆盖旧预算漏检、旧稿自动恢复、原意复核成功/失败/网络错误、有限重试、不覆盖原稿、留档、图片/付费片段保护、固定素材指纹旧稿仍能修复。
- 更新原有局部修稿测试，要求独立原意复核后才能接受新台词。生产构建通过。
- 没有调用真实文本/媒体模型、没有重试用户的生产任务、没有发布。
