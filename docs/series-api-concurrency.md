# API 并发与 ComfyUI 队列

2026-09-07，已随0.1.204发布，0.1.205继续包含此改动。用户要求 API 任务无需等待，只有 ComfyUI GPU 工作排队。

原问题是 Series 后台只要发现一个 running 就拒绝所有 claim，worker 也等待完整任务结束才继续领取。因此编剧/API 生图被另一集的视频生成阻塞。

## 当前行为

- worker 持续领取任务，每项拥有独立心跳、暂停信号与完成回执；有任务时连续领取，空闲时每3秒轮询。
- 不同项目并行；同项目在共享素材定稿后，不同集的编剧/生产并行。各项单独素材准备也可以并行。
- ComfyUI /prompt 仍交给原生 GPU 队列执行。等待视频不会占住其他任务的 API 执行机会。Story 的 ComfyUI 视频保留两项在途准备/轮询，GPU 实际串行。
- Story 互不依赖的 API 视频同批并发提交，不再每两项等整批完成；需要上一段尾帧的片段仍按依赖执行。
- 同集不同阶段、整季改写、全量共享素材准备、旧成稿迁移仍保护写入范围。共享素材准备尚在等待恢复时，后续编剧/生产不能越过依赖。
- 不同集仅合并自己的 episode；单项素材仅合并自己的 asset。每个租约保存独立 checkpointRevision，拒绝同任务迟到快照。既有成片记录保留。旧 worker 无 writeScope 按全项目独占处理。
- 原有暂停、失联恢复、任务号续查、付费提交去重及 Story 项目 Web Lock 保留。未改运行中的生产数据库。

## 验证与发布

新增 `tests/series-concurrency.test.mjs`，含真实 route + 临时数据库测试与实际 worker 组件转译执行测试：并发领取去重、交错保存、资产合并、同集隔离、准备依赖、暂停/过期租约、API尾帧依赖，以及首个任务未结束时仍领取下一项。

Series 全套152项通过；Next生产构建通过。测试使用模拟API，没有调用真实付费模型。

本次修改包括 Companion 内运行的 worker 和本机 Series API，生效需要网站与 Companion 同步发布。能力标志 `seriesConcurrentJobs=true`。0.1.204已发布并安装，随后0.1.205追加成稿台词超时修复。各版回执见out/releases/对应版本目录。
